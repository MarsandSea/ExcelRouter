# 数据脱敏：发出去只露该露的（设计方案）

> 状态：第 1 期（内核）已实现，2026-10-19。目标版本 v3.1。内核在 `core/desens.py`，测试在 `tests/test_desens.py`。
> 桌面版界面、技能接入在后面几期。

## 1. 要解决的问题

拆分已经做到「每个人只拿自己的行」，但行里的每个格子还是原样发出去。日常里常见的几种情况：

- 维系、催缴、回访清单发给社会渠道、外包、装维：要能认出是哪个客户，但不该拿到完整的证件号、银行卡号；
- 业绩通报、投诉通报发到群里：一个「张*、138****5678」就够了；
- 把表交给 AI 或厂家分析、做测试数据：要能统计、能关联同一个人，但认不出人；
- 汇总完要往上报：报上去的表不该带个人信息；收回来的表里，有人把完整证件号写在备注里。

现在的做法是手工写 `REPLACE` 公式、一列一列、一张表一张表地改，容易漏，漏了也发现不了。

## 2. 用起来是什么样

用户不用懂规则，**选用途就行**；规则按用途定好，个别列可以单独改：

| 用途 | 处理 |
|---|---|
| 内部下发 | 证件号、银行卡号打码，其余照发（外呼要完整号码） |
| 发群通报 | 识别出的个人信息全部打码，文字里夹带的号码也打码 |
| 交给 AI 分析 | 姓名、号码、证件、编码换成一致的代号（还能统计、关联，认不出人），地址到区县、日期到年 |
| 对外报送 | 个人信息整列清空，编码换成代号 |
| 自定义 | 只按指定的列处理，没指定的照发 |

三个入口，同一套规则：

- **拆分时顺带脱敏**：分组用真实值，分好之后再脱敏，产出（含「请核对_无归属」）里是脱敏后的值；
- **单独脱敏**一个表或一个文件夹：结果在输入旁「脱敏结果\{月日时分}结果\{原名}_脱敏.xlsx」；
- **汇总后另存脱敏版**：`{汇总表}_脱敏版.xlsx`，默认「对外报送」，原汇总表不动。

## 3. 识别什么、怎么处理

识别靠**列名关键词 + 抽样校验**（每列看前 200 行），号码类只看值也能认（六成以上合规）：

| 类型 | 识别依据 | 默认打码 |
|---|---|---|
| 手机号 | 11 位、1[3-9] 开头，认 +86 / 空格 / 连字符 | 138****5678 |
| 身份证号 | 18 位：出生日期合法 + 校验码；15 位老证只在列名对上时认 | 留前 6 后 4 |
| 银行卡号 | 16～19 位 + Luhn；列名对上时 12～19 位就算 | 留前 6 后 4 |
| 固定电话 | 0 开头的区号 + 号码 | 0760-****1234 |
| 姓名 | 列名（姓名、户名、联系人…）+ 2～4 个汉字 | 张*、欧阳**（认复姓） |
| 地址 | 列名 + 像地址的文字 | 留到镇街，后面打码 |
| 邮箱、ICCID、IMSI、IMEI | 格式校验 | 留首尾几位 |
| 宽带账号、客户 / 用户 / 账户编码 | 只看列名 | 留后 4 位 |
| 出生日期、经纬度 | 列名 + 值 | 只留年份 / 两位小数 |

列名里带「是否、类型、状态、归属、数量、率、有效期」之类的不算（「手机号码归属地」「证件类型」说的是属性，不是信息本身）。

**处理方式**对应 GB/T 37964-2019《个人信息去标识化指南》里的技术：

- 打码＝部分屏蔽；
- 换代号＝假名化：`HMAC-SHA256(种子, 类型|值)` 取 base32 前 10 位，加类型前缀（`TEL-` `IDN-` `NAM-`…）。同一份种子下，同类型同值同代号、跨文件一致；没有种子推不回原值。没给种子时每次随机，代号只在这一批里一致；
- 泛化＝地址到区县、日期到年、坐标两位小数、数字按最高位分段（5234 → 5000-6000）；
- 清空＝抑制。

**文字里夹带的号码**（备注、处理情况里写的手机号、身份证号、银行卡号）：带校验地就地打码，不乱遮订单号。
「内部下发」只遮证件号和卡号，其余用途三类都遮。

## 4. 五道闸：光洗不够，还要能发现没洗干净

1. **识别**：只回列名、类型、个数，不回任何值；
2. **确认**：方案里写清哪列怎么处理（界面 / 技能确认这一步，第 2、3 期）；
3. **处理**：在内存里改，源文件不动。顺序固定：**先按真实值分组 → 再清隐藏列 → 再脱敏**。脱敏时「保留公式」不生效（同行公式在对方打开时会按原写法重算，可能把原值拼回来）；
4. **复检**：产出落盘后重新只读扫一遍，处理过的类型里还有完整号码就算没洗干净——
   拆分：**不打 ZIP**，结果根目录写「未通过复检_请勿发出.txt」，`[SUMMARY]` 的 `desens.ok` 为 false；
   单独脱敏和脱敏版：先在内存里存成字节、复检，**过了才写到磁盘**，没过的文件根本不落盘。
   用户明确要照发的列复检时跳过；
5. **对账**：拆分原有的行数对账不变；报告里逐列写处理了几个格子。

宁可没产出，不出错产出。

## 5. 脱敏报告

结果根目录的「脱敏报告.xlsx」（脱敏版是「{原名}_脱敏报告.xlsx」），四页：

- **概要**：用途、处理了几列几格、文字里夹带几处、复检结论、代号种子是固定还是随机（种子本身不写）；
- **处理明细**：文件 / sheet / 列 / 识别为 / 处理方式 / 格数 / 示例——**示例是虚构值**；
- **复检**：没通过时列出位置和格数，不列内容；
- **指纹**：每个产出文件的 SHA-256。

报告、日志、`[SUMMARY]` 里都没有任何表格里的真实值。

## 6. 接口

```python
# config 新增可选键 desens（不填 = 不脱敏，拆分 / 汇总的行为和以前完全一样）
config["desens"] = "发群通报"
config["desens"] = {"scene": "交给AI分析",
                    "columns": {"备注": "clear", "客户姓名": "keep"},   # 按列名覆盖：mask/pseudo/generalize/clear/keep
                    "notes": True,                                     # 文字里夹带的号码
                    "seed": "00ff…"}                                   # 代号种子（十六进制）；不填 = 本次随机

run_split(config, ...)          # [SUMMARY] 多 desens: {scene, columns, cells, embedded, residual, ok}
merge_tables / run_collect      # [SUMMARY] 多 desens 和 desens_output
run_desens(config, log_fn, progress_fn, stop_flag)   # 签名同 run_split；[SUMMARY] mode = "desens"
```

`process_file` 多一个可选参数 `desens_job`（`core.desens.Job`），由 `run_split` 建好传入，一批共用一份种子和统计。

`core/desens.py` 的规矩同 `collect.py` / `xlio.py`：不导入 pandas、不用 shutil、不读环境变量、不删文件、不起进程，
注释和字符串避开内部打包的禁用字眼（`tests/test_xlio.py` 的清洁度检查守着）——内部技能会原样带上它。

## 7. 明确不做

- PDF、Word 里的内容脱敏（PDF 做不到可靠涂黑，做了反而给人假安全感）；
- 表头上方的标题、sheet 名、文件名（按人拆时文件名就是人名）、下拉选项里的内容；
- 单独脱敏时批注、图片、图表、透视表缓存、文档属性**直接去掉**（可能带原始数据，又不在单元格里）；
- 识别是规则匹配，**不保证找全**，所以有复检和「自定义」兜底；
- 打码不可逆；代号的「还原回填」放第 4 期，做法是拿原表重算对上，不存对照表；
- 不替用户判断法律类别，只提供处理手段。

## 9. 测试

`tests/test_desens.py`：各校验器与误报（公司名不算人名、归属地不算号码）、各处理方式边界（+86、空格、复姓、
少数民族名、占位「无」）、代号确定性、文字夹带；拆分接入（内部下发照发号码、按要打码的列拆时分组用真实值、
隐藏列照清、不开脱敏时产出不变、复检不过不打 ZIP、报告不含真实值、报告不进分组包、保留公式不生效）；
单独脱敏（隐藏 sheet / 批注去掉、地址泛化、结果目录不会被下次当输入、复检不过不落盘）；汇总后脱敏版。
不开脱敏时 `tests/golden/` 逐格快照照常通过。
