# 方案：把一次设置存下来，下个月一键套用、发给同事也能用（设计方案）

> 状态：草案，2026-10-11。目标版本 v3.0。借鉴：OpenRefine 把操作历史导出成 JSON，在另一份结构相同的数据上「一键重放」。

## 1. 要解决的问题

用户的任务几乎都按月重复：每月工资条、网格月报、季度走访。现在：

- `user_config.json` 只有**一个槽位**，记的是「上一次」。这个月先拆了工资条、又做了一次网格下发，下个月再拆工资条时，字段、到人、填写列都得重新选；
- 同事要做同样的事，只能口头教「先选这个、再勾那个」；
- 技能和桌面版各管各的参数，在桌面版调好的做法没法交给 AI 去跑。

## 2. 方案是什么

一个小 JSON 文件，存的是「怎么做」，**不存「对哪些文件做」**：

```json
{
  "excelrouter_recipe": 1,
  "name": "九月网格走访下发",
  "mode": "excel",
  "app": "3.0.0",
  "created": "2026-10-11T15:20:00",
  "note": "按网格拆，客户经理填走访日期和结果，15 号收",
  "settings": {
    "split_column": "网格",
    "header_mode": "auto",
    "make_zip": true,
    "to_person": false,
    "preserve_format": true,
    "fill_columns": "走访日期（日期）、走访结果（已走访/未走访/拒访）",
    "skip_values": ["合计", "小计", "总计", "平均", ""]
  },
  "hints": {"input_name": "九月走访总表.xlsx", "columns": ["网格", "客户名称", "走访日期", "走访结果"]}
}
```

### 2.1 存哪些键：按模式定白名单

白名单放在 core 里，桌面版和技能共用：

| 模式 | 存 | 不存 |
|---|---|---|
| excel（拆分） | `split_column` `selected_values` `header_mode` `header_row` `grid_keys` `id_keys` `to_person` `person_column` `person_file_filter` `make_zip` `merge_across_files` `preserve_format` `keep_formulas` `exact_match` `value_alias_map` `skip_values` `fill_columns` | `input_path` `output_path` `due` |
| collect（汇总） | `collect_check` `collect_expect` `collect_required` `collect_by` `collect_title` `header_mode` `header_row` | `collect_input_path` `collect_record` `collect_due` |
| pdf（文件加密分发） | `pdf_grid_column` `pdf_password_column` `pdf_receiver_column` `pdf_encrypt` `pdf_watermark` `pdf_watermark_text` `pdf_watermark_opacity` `pdf_watermark_angle` | `pdf_input_paths` `pdf_mapping_path` |
| 全部 | | `window_geometry` `ui_scale` `appearance_mode` `auto_open_output` |

几个取舍：

- **路径一律不存**：每个月文件不同，存了反而会套到上个月的文件上；分享给同事时，路径还会暴露对方电脑的目录结构。`hints.input_name` 只用来提示「上次用的是哪张表」，不参与任何操作；
- **截止时间不存**：每次都不一样，套用后留空，开始前照常提醒；
- **应交名单（`collect_expect`）存**：网格名、单位名这类名单每个月基本一样，这正是复用的价值所在。分享前界面提示一句「这个方案里有应交名单 12 个」；
- **`hints.columns` 只存列名**（不存数据），用于套用时比对「这张表和上次的结构一样不一样」。

### 2.2 套用时的检查（OpenRefine 的教训：列名得对得上）

OpenRefine 的操作历史要求新数据的列名和原来一样，否则重放出错。套用方案时也一样，读完当前表的列以后要比一遍：

- 拆分字段、到人字段、按哪一列分人在这张表里找不到：**明确提示**「方案里的拆分字段『部门』这张表里没有」，并且**不准自动改成推荐的列**。现在 `_on_columns` 遇到保存值失效会用 `_recommend_split` 自动预选，套用方案时必须关掉这个行为，否则会静默换成别的列，按错的列拆完才发现；
- 填写列在表里没有：照现在的规则，下发时加在最后，日志里说一句；
- 列结构和 `hints.columns` 差别很大（对上的不到一半）：提示「这张表和方案上次用的表不太一样，请确认」。

## 3. 桌面版

### 3.1 入口：页脚工具条一个「📋 方案」菜单

不进主流程，不增加第一眼的复杂度：

```
📋 方案 ▾
   存为方案…
   打开方案…
   ─────────
   九月网格走访下发     ← 最近 5 个
   每月工资条
```

- 存：默认存到程序目录下的「我的方案」文件夹（和 `user_config.json` 同一个位置，绿色版拷走也带着），文件名就是方案名；
- 最近列表记在 `user_config.json` 的新键 `recent_recipes`（路径列表，最多 5 个）；
- **拖一个方案文件进窗口就是打开它**。`_parse_drop_paths` 本身不挑类型，但各拖放入口（`_on_drop_input`、`_on_drop_collect` 等）目前只收 .xlsx / .xls，要在入口里加一条 .json 分流。注意「下发记录.json」也是 .json：靠文件里有没有 `excelrouter_recipe` 键来区分，下发记录拖进汇总模式时照旧当下发记录用；
- 套用后：切到对应模式 → 填好各个控件 → 如果当前已经选了表就重新扫描并做 §2.2 的检查 → 日志写「已套用方案『九月网格走访下发』：拆分字段 = 网格，填写列 = 走访日期、走访结果」。

### 3.2 让人发现它

成功跑完一次以后，结果区多一个小链接「存成方案，下个月一键用」。规则：

- 当前设置和最近的某个方案完全一样时不出现（已经是方案了）；
- 点过一次「不再提示」就永远不出现。

## 4. 技能

- `er_split` / `er_check` / `er_merge` / `er_pdf_dist` 都加 `--recipe 方案.json`；**命令行明确给出的参数优先于方案**；方案的模式和脚本对不上时报错（拿拆分方案去跑查收）；
- 都加 `--save-recipe 路径`：把这次实际用的设置存成方案；
- SKILL.md 加一段：用户说「按上次的做法」「用这个方案」时找方案文件；用户对结果满意时，可以问一句要不要存成方案。

这样桌面版存的方案可以交给 AI 跑，AI 存的方案桌面版也能打开，格式只有一份。

## 5. 代码结构

新模块 `core/recipe.py`（只用标准库 json，不 import gui，不 import pandas）：

```python
RECIPE_KEYS = {"excel": [...], "collect": [...], "pdf": [...]}
make_recipe(cfg, mode, name, note="", columns=None) -> dict
save_recipe(recipe, path)
load_recipe(path) -> (recipe, warnings)          # 版本、模式、键名、类型校验
apply_recipe(cfg, recipe) -> (new_cfg, changed, warnings)
check_columns(recipe, columns) -> warnings        # §2.2 的检查
```

- 类型校验以默认配置为准：布尔就是布尔、列表就是列表，类型对不上的键丢弃并警告。**方案文件会在同事之间传，必须当作外来数据处理**：只认白名单里的键，文字长度设上限，绝不执行、绝不当路径打开；
- 不认识的键（比如更新版本写的）忽略并提示「这个方案是新版本做的，有 N 项设置这个版本不支持」；
- `publish-skill.yml` 本来就整个复制 `core/`，技能自动带上这个模块；内部 MobileWork 版只带 `collect.py`，不受影响。

## 6. 分期

- **P1**：`core/recipe.py` + 单测；桌面版「方案」菜单（存、打开、最近）+ 套用检查；拖放打开。
- **P2**：技能 `--recipe` / `--save-recipe`；结果区「存成方案」提示。
- **P3**：仓库里放两三个**示例方案**（工资条一人一份、网格下发回收、按月汇总），配上 `examples/` 里的样本表，兼当新手引导：「从示例开始」。

## 7. 测试

- 往返：配置 → 方案 → 套回去，白名单里的键原样恢复，路径和截止时间不出现在方案里；
- 外来数据：类型错的键丢弃、超长文字截断、未知键忽略、模式不对报错、损坏的 JSON 友好报错；
- 列检查：拆分字段不在表里时出警告，**且配置里的拆分字段没有被换成推荐列**；
- 技能：`--recipe` 和明确参数同时给时，明确参数生效。
