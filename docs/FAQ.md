## 我的数据会被上传吗？安全吗？

**不会。** 程序**不联网、没有任何遥测、不做自动上报**，拔掉网线可以照常完成全部拆分工作。

- 所有读写都发生在你自己电脑的磁盘上，输出结果就在你指定的「拆分结果」目录里。
- 唯一会打开网络的动作，是你**自己主动点击**界面上的「💬 反馈建议」按钮——那会用系统浏览器
  打开一个匿名问卷链接，不会携带任何你的数据。
- 全部源码开源（MIT），可以自行审查，也可以 `pip install -r requirements.txt && python main.py`
  直接从源码运行，或用 `build.bat` 自己打包。

## 收费吗？公司内部用、商用可以吗？

**完全免费，MIT 开源协议。** 个人使用、公司内部使用、商业场景使用都可以，不需要授权、不需要
付费、没有功能限制和使用次数限制，也没有广告或账号注册。二次开发、修改分发同样允许，
**保留原作者版权声明**即可（这是 MIT 协议的唯一要求）。

## 能把多层合并表头「拆平」成单行表头吗？

**不能，这是刻意不做的。** 本工具的设计目标是**原样保留**你原来的表头——包括大标题、分组
标签、跨列合并单元格在内的多行复杂表头，拆出来的文件和源表长得一模一样，接收人拿到就能直接
用。「表头扁平化 / 降维」属于数据清洗范畴，方向正相反，不在本工具范围内。

工具会**自动识别**表头在第几行（前 15 行启发式扫描），识别不准时可以在「高级设置」里手动
指定表头行号。

---

## 能反过来把多个 Excel 合并成一个吗？

**这不是一个通用的合并工具。** 唯一的合并能力是**拆分过程中的合并**：在「高级设置」勾选
「跨文件合并汇总」后，同一个取值（如「华北」）在多个源文件里的数据会被合并进同一个结果文件
（典型场景：1–5 月每月一份表，按区域拆分并把每个区域的 5 个月合成一张表）。

如果你要的是「把一堆结构不同的表原样堆成一个大表」，请另找合并工具。

## 和 VBA / Power Query / 在线拆分网站比有什么区别？

| 做法 | 批量多文件 | 保留原格式 | 数据安全 | 上手成本 |
|---|---|---|---|---|
| 手动筛选 + 复制粘贴 | ❌ | ✅ | ✅ 本地 | 低，但极耗时 |
| 在线拆分网站 | 通常有限 | ⚠️ 常丢格式 | ❌ 需上传数据 | 低 |
| VBA 宏 | ✅ | 取决于代码 | ✅ 本地 | 高，要会写/改代码 |
| Power Query | ✅ | ❌ 输出是纯数据表 | ✅ 本地 | 中高，要学 M 语言 |
| **ExcelRouter** | ✅ 整个文件夹 | ✅ 含多层复杂表头 | ✅ 全程本机 | 低，三步点击 |

最大的差异在两点：**保留复杂表头格式**（Power Query 会把表变成规整的纯数据表，原来的大标题、
分组表头、字体边框全没了）和**整个文件夹批量 + 自动打包 ZIP 分发**。

## 拆出来的文件名是怎么决定的？能自定义吗？

文件名就是**那个取值本身**，如按「部门」拆就得到 `销售部.xlsx`、`财务部.xlsx`。取值里如果
含有 Windows 文件名非法字符（`\ / : * ? " < > |`）会自动替换成下划线，取值为空则用「未命名」。

目前**不支持自定义文件名模板**。批量模式下的目录结构是
`{取值}/汇总/{原文件名}.xlsx` 与 `{取值}/到人/{姓名}.xlsx`，并按取值打包成 `{取值}.zip`。

## 一次能拆多大的表？多少行、多少个文件？

没有硬性上限，实际瓶颈是内存和耐心：

- **单文件几万行**没问题，会有实时进度和心跳日志（见
  [大文件那条](#处理大文件几万行时界面卡住像死机了一样是不是崩溃了)）。
- **整个文件夹上百个文件**也能跑，逐个处理，单个文件出错不会中断整体，只记进日志继续。
- 需要注意的是**「跨文件合并汇总」+ 宽表（几百列）+ 大批量文件**的组合：合并模式下所有输出
  工作簿要留在内存里直到最后统一保存，内存占用会明显升高。所以该选项**默认关闭**，需要时
  再去「高级设置」里勾选。

## 杀毒软件误报

**Q：下载的 exe 被 Windows Defender / 杀毒软件报「木马」「病毒」，能不能用？**

能用，这是**误报**（False Positive），不是真的有病毒。原因：

- 单文件版（`ExcelRouter-vX.X.X.exe`）每次启动会把内部的 Python 运行时和依赖
  解压到系统临时目录再执行，这种「自解压后执行」的行为模式和部分木马的启动
  方式相似，容易触发杀毒软件的**启发式扫描**误判。
- 本工具用 PyInstaller 打包，官方预编译的打包引导程序（Bootloader）也被
  许多其他打包了恶意程序的软件用过，导致该 Bootloader 的特征码被一些厂商
  标记为可疑，这与本项目代码本身无关。

**怎么办：**
1. **优先下载 ZIP 版**（`ExcelRouter-vX.X.X-win64.zip`，解压后运行里面的 exe）——
   这种打包方式不需要运行时自解压，基本不会触发上述误报。
2. 如果杀毒软件拦截了，选择「允许运行」/「信任此文件」，或临时关闭实时防护后运行一次。
3. 本项目完全开源，代码在 [GitHub 仓库](../) 可自行审查，也欢迎自己用
   `pip install -r requirements.txt && python main.py` 从源码直接运行，
   或者自己用 `build.bat` 本地打包，生成的文件不经过第三方分发，更不容易被拦截。
4. 如果你想帮忙推动误报修复，可以去
   [Microsoft 误报反馈门户](https://www.microsoft.com/en-us/wdsi/filesubmission)
   提交一次，通常几天内云端库会更新。

## 拆分后某一列（如「到账金额」）是空白的

**Q：数据源里那一列明明有公式和数字，拆分出来却是空白？**

本工具通过 pandas 读取的是 Excel **公式的缓存计算结果**，不会重新计算公式。

- 如果这份 Excel 是**用 Excel/WPS 打开并保存过**的，公式一定带缓存值，正常显示。
- 如果这份 Excel 是**程序生成、或公式从未在 Excel 里被计算/保存过**，就没有
  缓存值，读出来就是空白。

**怎么办：** 用 Excel 或 WPS 打开这份表格，`Ctrl+S` 直接另存（触发一次公式计算），
再用本工具处理。工具本身也会在处理前**自动检测**这种情况并在日志里提前预警，
不会让你在拆完之后才发现数据是空的。

## 勾了「保留公式」，为什么有的公式还是变成了数字

**Q：我勾选了「保留公式」，输出文件里某些列的公式还是变成了固定数值，是不是没生效？**

这是**故意的**，不是 bug。拆分会把符合条件的行挑出来重新排列，行号必然发生变化
（比如源表第 100 行的记录，拆出来后可能是第 5 行）：

- **同一行内**的公式（如「金额 = 单价 × 数量」，只引用自己这一行的其它列）能安全地
  把行号平移到新位置，结果依然正确，会**保留为活公式**。
- **跨行汇总 / 跨表引用**的公式（如「合计 = SUM(D2:D100)」、`VLOOKUP` 查其它表）
  引用的行已经被过滤或搬到别处，没法平移，硬保留会显示错误结果甚至 `#REF!`——
  这种情况工具会**主动转成当前的计算数值**，而不是给你一个算错的公式。

简单说：保证不了正确、就不装成公式。这样接收人看到的公式一定是对的，数值列也是对的，
不会因为一个显示错误的公式反而引发新的争议。

## `.xls`（旧版 Excel 格式）支持到什么程度

`.xls` 文件会被自动转换成 `.xlsx` 再处理，**能拆分、数据完整**，但转换过程中
**无法保留原始的字体、颜色、边框等格式**，只保留数据本身。如果格式很重要，
建议先用 Excel/WPS 把 `.xls` 另存为 `.xlsx` 再处理。

## 数据区的合并单元格会保留吗

**不会。** 数据区域（表头以下的数据行）如果有合并单元格，拆分后会被展开为
普通单元格（每行独立填值）。**表头区域的合并单元格会正常保留**（比如大标题
跨列合并、分组标签合并等），这也是三层复杂表头能被正确识别的关键设计。

## 单文件版启动比较慢，正常吗

正常。单文件版（onefile）每次启动都要先把依赖解压到临时目录，这个过程通常
需要几秒钟，属于 PyInstaller onefile 模式的固有特性。如果比较介意，改用
ZIP（onedir）版——解压一次后，之后每次启动都是直接运行文件夹里的 exe，
没有这个解压过程，启动明显更快。

## 处理大文件（几万行）时界面卡住、像死机了一样，是不是崩溃了

**不是崩溃，是真的在算。** v2.4 之前，进度条只按「文件数」推进——如果输入只有 1 个大文件，
进度条一开始就跳到头，中间处理的十几秒到几十秒里界面看起来毫无反应，容易被误认为卡死。

v2.4 起已改进：
- 进度条现在反映**文件内部**的真实阶段（读取 → 读格式 → 逐组拆分 → 保存），几万行的大文件
  也会平滑推进，不会卡在某个数字不动。
- 点击「开始处理」的一瞬间，进度条立刻变成滚动动画、日志立刻打出「已开始，正在扫描输入…」，
  不会有几秒钟的静默期。
- 日志里会每写入约 2000 行打一条「…已拆分写入 N 行」的心跳，大文件也能看到进度在走。
- 处理过程中让出了 CPU 时间片给界面线程，窗口不会失去响应（可以正常最小化/拖动）。

如果升级后仍然长时间（几分钟以上）没有任何新日志、进度条也不动，才说明可能真的卡住了，
请提 [Issue](../../issues) 并附上大致的行数和列数。

## 「到人」+「ZIP」这套输出结构具体是怎样的

开启「到人」后，每次拆分会同时产出**两套**结果：

- **汇总**：按拆分字段（如「部门」）拆分、跨文件合并后的完整表
- **到人**：在汇总基础上，再按你指定的第二列（如「姓名」）拆到每个人的独立文件

批量模式（输入是文件夹）下，每个主取值会打包成一个 ZIP，比如 `销售部.zip`，
里面同时包含 `汇总/`（该部门的完整数据）和 `到人/`（该部门每个人的单独文件），
可以直接把整个 ZIP 发给对应部门负责人。

## PDF 加密分发：密码忘了能找回吗

**不能。** 加密用的是 PDF 标准的打开密码（AES-256），没有任何后门，密码丢了
文件就打不开了。每次分发都会在输出目录生成一份「分发清单.xlsx」记录每个网格的
密码，**请自己留存好这份清单**；重新跑一次分发（用同一份映射清单）也能重新生成。

---

## PDF 水印里的中文变成了「?」

水印需要一款中文字体。程序会自动在系统字体目录里找黑体（simhei.ttf）、等线
（Deng.ttf）等常见字体，绝大多数中文 Windows 都自带。如果你的系统精简过字体、
日志里出现「未找到中文字体」的警告，安装任意一款中文 TTF 字体（如黑体）即可。
英文和数字不受影响。

## 分发清单能和加密文件一起发出去吗

**不要。** 分发清单里是**明文密码**（不然你自己也没法通知各网格密码），它只
给分发人自己对照使用。发文件时只发对应网格文件夹里的 PDF，密码通过单独渠道
（如逐个私聊）告知。

## 能把文件 / 文件夹直接拖进窗口吗

可以（v2.7 起）。把 Excel 文件或装表格的文件夹拖到①号卡片上即可开始；PDF 加密分发
模式下，PDF 和映射清单也都可以拖。拖不进来通常是用了过旧的版本，请到 Releases 下载最新版。

## 怎么只拆其中几个部门 / 取值

选定「拆分字段」后，②号卡片会自动列出「将拆成哪几组」。点旁边的
**「▸ 查看/勾选分组」**，勾掉不需要的分组即可；全选则等于拆分全部。
勾选结果会自动记住，下次打开不用重设。（等效的高级设置：手填「只拆这些取值」。）

## PDF 加密分发：没有密码清单怎么办

两步都有招：

1. **没有清单本身** —— ②号卡片点「生成模板」，一键产出带示例和填写说明的
   「映射清单模板.xlsx」，填上网格名即可；
2. **没有密码思路** —— 只选好「网格列」、不选「密码列」，点「开始分发」时会问你是否
   **自动生成随机密码**（每个网格一个 8 位随机密码），确认后会在原清单旁边另存一份
   「_含密码.xlsx」并继续分发。

注意：随机密码只存在那份清单里，丢失无法找回，请保管好。

## 有没有 Mac 版 / Linux 版 / 在线版

**没有，只有 Windows 版**（Windows 10 / 11 64 位，免安装，解压即用）。

- **在线版**：从数据保密性角度考虑不做在线版——在线版意味着你必须把表格上传到别人的
  服务器上，而「数据不出本机」是本产品底线，不会为了方便而牺牲它。
- **Mac / Linux**：暂不提供，待 GitHub 或 Gitee 点赞量（Star）100+ 后会增加。
