# 填报规则：下发时防错、查收时复核（设计方案）

> 状态：方案已定（2026-10-11，见文末「已定」），待实现。目标版本 v3.0。
> 借鉴：ODK 的 XLSForm（在 Excel 里写表单规则）、pandera / Frictionless（一次查全、错误有固定编码）。

## 1. 要解决的问题

现在「让对方填写的列」只做了两件事：标浅黄、解锁。收回来只能查出**漏填**，查不出**填错**：

- 「走访结果」有人写「已走访」，有人写「已访」「走访了」「√」，汇总后没法筛选、计数；
- 「走访日期」有人写 `2026.10.5`、`10.5`、`国庆后`，Excel 认不出是日期，排不了序；
- 「户数」有人写 `3户`、`约5`，求和时被当成文字。

这些问题现在要等汇总以后人工逐行看才发现，再回头催人改，等于多一轮。

**思路**：规则只写一次，用两次。
1. **下发时**写成 Excel 原生的「数据验证」，填的人当场就填不错（下拉框、日期校验）；
2. **查收时**按同一份规则再查一遍。必须再查：**粘贴会绕过数据验证**，老版本 WPS、手机端也未必拦得住。

## 2. 不做什么

- 不做跨列条件（「走访结果=拒访 时 拒访原因必填」）。XLSForm 的 `relevant` 很强，但对办公人员太难写，先不碰。
- 不做「规则表模板」让用户在 Excel 里编辑规则（PDF 模式那种「生成模板」）。v1 只用一行文字写规则，有真实需求再加。
- 不按列名猜类型（比如列名带「日期」就自动加日期校验）。猜错会拦住人家正常填写，代价比不猜大。见 §11 第 4 条。
- 不在通报里回显填错的值。通报要发群，回显等于把单元格内容贴进群里，违背「不留内容」的原则；只说**哪一列、第几行、错在哪类**。

## 3. 用户怎么写规则：沿用现有输入框，加括号

**不加新控件。** ② 卡片「让对方填写的列」那个输入框，括号里写规则：

```
走访日期（日期）、走访结果（已走访/未走访/拒访）、户数（整数）、联系电话（手机号）、备注（选填）
```

| 括号里写 | 含义 | Excel 里的效果 | 查收时查什么 |
|---|---|---|---|
| `A/B/C`（含 `/` 或 `｜`） | 只能从这几项里选 | 下拉框，填别的会被拦 | 不在选项里 |
| `日期` | 必须是日期 | 填非日期会被拦；格子设成 `yyyy-mm-dd` 显示 | 不是日期 |
| `数字` | 必须是数字（可带小数） | 填文字会被拦 | 不是数字 |
| `整数` | 必须是整数 | 填小数、文字会被拦 | 不是整数 |
| `手机号` | 必须是 11 位手机号 | 不是 1 开头的 11 位数字会被拦；格子设成文本格式 | 不是手机号 |
| `电话` | 手机号或座机都行 | 不加数据验证（座机写法太多，Excel 公式拦不准） | 不是电话号码 |
| `选填` | 可以不填 | 无 | 不查漏填（填了照样查格式） |
| 可以组合 | `联系人数（整数 选填）` | | |
| 不写括号 | 和现在完全一样 | 只标黄解锁 | 只查漏填 |

解析规则（新函数 `parse_fill_spec(text) -> [(列名, rule)]`）：

- 括号支持全角 `（）` 和半角 `()`；
- **括号外**仍按现在 `split_names` 的分隔符切（`、,，;；` 和空白），旧写法 `走访日期 走访结果` 不受影响；
- **括号内**按空白、逗号切成若干词：含 `/` 或 `｜` 的是选项表；`日期 / 数字 / 整数 / 手机号 / 电话` 是类型（`手机`、`手机号码` 也认）；`选填` 是标记；
- 看不懂的词（比如 `（必填）`、`（YYYY-MM-DD）`）**不报错、不拦人**，这一列按「只查漏填」处理，日志里说一句「看不懂『YYYY-MM-DD』，『走访日期』按普通文字处理；日期请写（日期）」；
- 一列同时写了选项和类型（`（日期 已走访/未走访）`），以选项为准，日志提示一句。

界面上在输入框下面实时回显识别结果，让人确认没写错（P2，见 §9）：

```
识别到：走访日期 = 日期；走访结果 = 3 个选项；户数 = 整数；备注 = 选填
```

## 4. 规则模型

```python
rule = {"type": "text" | "list" | "date" | "number" | "whole" | "mobile" | "phone",
        "options": [...],       # 仅 list
        "optional": False}      # 选填
```

刻意只留这几种。手机号在网格、客户类工作里太常见，放进 P1（作者 2026-10-11 问到）；身份证号、数值范围（`数字 0~100`）放到 P3，模型上预留 `min` / `max` / `pattern` 键就行，不用现在实现。

## 5. 下发时（`prepare_issue` / `_mark_fill`）

在现在「标黄、解锁」那一步之后，对每个**有规则**的填写列：

**5.1 写数据验证**（`openpyxl.worksheet.datavalidation.DataValidation`，openpyxl 自带，不加依赖）

| 类型 | 参数 |
|---|---|
| list | `type="list"`，选项直接写进下拉框：`formula1='"已走访,未走访,拒访"'`。Excel 规定这串文字最多 255 个字符（约 40～60 个短选项），超长或选项里有英文逗号时**这一列不加下拉框**，只在查收时检查，日志里说一句「选项太多，没加下拉框，收回来照样查」 |
| date | `type="date", operator="greaterThan", formula1="1"`（任何真日期都放行），同时把这列数据格的 `number_format` 设为 `yyyy-mm-dd` |
| number | `type="decimal", operator="between", formula1="-1E+15", formula2="1E+15"` |
| whole | `type="whole"`，范围同上 |
| mobile | `type="custom"`，`formula1='AND(LEN(B3)=11,LEFT(B3,1)="1",ISNUMBER(--B3))'`。`B3` 是作用范围左上角的格子，Excel 按相对位置把公式套到整列。这列数据格的 `number_format` 设为 `@`（文本），防止号码被当成数字后显示成科学计数法。沙箱已验证 openpyxl 能写入、读回 |
| phone | 不加数据验证，只设文本格式和提示语；全靠查收 |

所有规则共同的参数：

- `allow_blank=True`：Excel 的数据验证**本来就管不了空格子**，漏填交给查收；
- **`showErrorMessage=True` 必须显式写**。沙箱实测 openpyxl 3.1.5 默认是 False，不写的话 Excel 静默接受任何输入，下拉框形同虚设；
- `errorStyle="stop"`；`errorTitle` 写列名，`error` 写人话，比如「请从下拉里选：已走访 / 未走访 / 拒访」「请填日期，比如 2026-10-15」；
- `showInputMessage=True` + `prompt`：选中格子就浮出一行提示（标题 ≤ 32 字、内容 ≤ 255 字，超出截断）；
- 作用范围：数据第一行到最后一行（和标黄的范围一样）。现在其余格子是锁定的，对方本来就加不了行，不用预留空行。

沙箱已验证：数据验证在 openpyxl 读回 / 再存一遍后都保留。

> 超长选项不用「把选项写进某个 sheet、下拉框引用那片格子」的做法（作者 2026-10-11 定）：这种写法在 WPS 里能不能用没把握，而真要 60 个以上选项的场景很少，不值得为它多一个不确定点。

**5.2「填报说明」sheet 加一张规则表**（XLSForm 的思路：规则就在表里，人看得见）

在现有 6 行键值对下面空一行，接着写：

```
列名        要求                  可填的值 / 示例
走访日期    必填 · 日期            2026-10-15
走访结果    必填 · 从下拉里选      已走访 / 未走访 / 拒访
户数        必填 · 整数            3
备注        选填
```

「填报说明」sheet 本来就会被 `scan` 跳过，不会混进汇总；它现在没有保护，这次顺手加上工作表保护（不设口令），防止对方无意中改了「填报对象」，查收时认不出是谁交的。

**5.3 下发记录.json 加两个键**（`version` 仍为 1，只加键；旧版本读到会忽略，退回只查漏填）

```json
"fill_columns": ["走访日期", "走访结果", "户数", "备注"],
"required": ["走访日期", "走访结果", "户数"],
"rules": {"走访日期": {"type": "date"},
          "走访结果": {"type": "list", "options": ["已走访", "未走访", "拒访"]},
          "户数": {"type": "whole"}}
```

- `fill_columns` 保持**纯列名**，不带括号，旧代码照样能用；
- 选项是**下发人写的规则**，不是任何人填的内容，不违反「下发记录不存单元格内容」。CLAUDE.md 那句要补上这层区分。

**以查收方为准**：查收时只认下发记录里的规则，不读交回文件里「填报说明」的规则表。后者对方能改，只给人看。

## 6. 查收时（`scan` → `analyze` → 通报 / 进度表 / 汇总）

**6.1 `scan` / `_scan_sheet`**：加 `rules` 参数（和 `fp_keys` 一样传进去），流式检查每个**非空**格子，只记**行号和错误编码**，不记值，和现有 `blank_rows` 同一套路：

```python
entry["bad_rows"] = {列键: {"not_in_options": [行号...], "not_date": [...]}}   # 每类最多 BLANK_KEEP 个
entry["nbad"] = {列键: 个数}
```

`rows_mode`（按列分人的总表）的 `groups` 里同样记一份。

**6.2 判定口径**（宽进：能**无歧义地**认出来的算对，不催改，汇总时自动改成规范写法，见 §6.7）

判对错和汇总时改写共用**一个函数** `_coerce(value, rule, year) -> (ok, 规范值)`。查收说「对」的，汇总一定改得过来；改不过来的，查收一定已经报错。两边口径不会对不上。

| 类型 | 算对（并能规整） | 算错（编码） |
|---|---|---|
| list | 去掉首尾空白后和某个选项相同；全角半角、大小写不同也算对 | `not_in_options` |
| date | 见 §6.7 的日期表 | `not_date` |
| number | 数值；去掉千分位逗号、空白后能转成数字的文字（`1,200`）；数字后面跟 1～2 个汉字单位（`3户`、`12人`） | `not_number` |
| whole | 同上且是整数（`3.0` 算对） | `not_whole` |

| mobile | 去掉空格和 `-`、全角数字转半角、去掉开头的 `+86` / `86` / `0086` 后，是 `1[3-9]` 开头的 11 位数字；存成数字的 `13800138000.0` 也算 | `not_mobile` |
| phone | 符合手机号；或者是座机：`0` 开头的 3～4 位区号加 7～8 位号码，区号后有没有 `-`、带不带「转xxx」分机都算 | `not_phone` |

数字**前面**有字的（`约5`、`≥3`）不算对：去掉「约」会改变意思，要让本人改。

一格写了两个号码（`138…/139…`）算错：汇总后没法用。要么让本人只留一个，要么下发时多给一列「备用电话」。

漏填沿用现有编码 `blank`。这五个编码定下来以后不改，通报、进度表和技能的 JSON 都从编码渲染文字。研究里说的「错误有固定编码」先从这里起步，不动现有的漏填、改动结构。

**6.3 新状态「填写有误」**

```
空表 > 有漏填 > 填写有误 > 有改动 > 表头对不上 > 合格
```

- `ST_INVALID = "填写有误"`，`_RANK` 顺延，`_STATUS_COLOR` 用橙色（和有漏填同色）；
- 每个人新增 `p["invalid"] = [{"col", "code", "count", "rows"}]`；
- `counts()` 加 `"invalid"`。`[SUMMARY]` 会跟着带上，GUI `app.py:1626` 的问题列表和技能 `er_check.py:124` 的 counts 白名单各加一项。

**6.4 通报**（`notice_text` / `_remind`）

```
填写有误（2）：
  东城：走访结果 第 5、7 行不在选项里（应为 已走访 / 未走访 / 拒访）
  西城：走访日期 第 9 行不是日期；户数 第 3 行不是整数
```

催办话术：「东城：【九月走访】你交的表填写有误：走访结果 第 5、7 行不在选项里（应为 已走访 / 未走访 / 拒访）。请于 10月15日 18:00 前改好重新交。」

选项超过 6 个时，括号里只写「请从下拉里选」，不把选项全列出来。

**6.5 回收进度.xlsx**：主表加一列「填写有误」；「漏填明细」改名「问题明细」，加一列「问题」（漏填 / 不在选项里 / 不是日期…）。改名前先 grep 技能和内部版有没有按 sheet 名读它，有就保留旧名。

**6.6 汇总结果标色**：`_merge_sheet` 现在给漏填格子标浅红（`BLANK_FILL`），这次给填错的格子标浅橙（`FFEB9C`）。

**6.7 汇总时自动规整写法**（作者 2026-10-11 定：文字日期查收时算对，汇总时统一改成真日期）

有规则的列，`_merge_sheet` 写值之前过一遍 `_coerce`：认得出的改成规范值；认不出的保持原样、标浅橙。**只改汇总结果，交回来的原文件一个字不动。**

日期的认法（`year` 取下发记录的创建日期，没有记录时取今天）：

| 原来的写法 | 存储形式 | 改成 | 说明 |
|---|---|---|---|
| 真日期 | 日期 | 原值，统一显示 `yyyy-mm-dd` | |
| `2026-10-5` `2026/10/5` `2026.10.5` `2026年10月5日` `20261005` | 文字 | 2026-10-05 | 有年份，无歧义 |
| `10月5日` `10-5` `10/5` `10.5` | 文字 | 补上年份 | 年份取离下发日期**最近**的那一年：12 月下发、填「1月3日」，算次年 |
| `46300` 这类数 | 数字 | 对应日期 | 只认 1990～2100 年对应的序号。别的表复制过来、格式丢了的日期就是这样 |
| `10.5` `10.1` | **数字** | **不改，标浅橙** | 有歧义：「10.10」存成数字就是 10.1，分不清是 10月1日还是 10月10日。宁可不改，也不改错 |
| `国庆后` `10月上旬` | 文字 | 不改，标浅橙 | 查收时已经报「不是日期」 |

数字：`1,200` → 1200，`3户` → 3，文字转成真数字（右对齐、能求和）。
手机号：`138 0013 8000`、`138-0013-8000`、`+86 13800138000`、存成数字的 13800138000，统一成文本 `13800138000`。
座机：`010 12345678`、`(010)12345678` 统一成 `010-12345678`，分机原样留在后面。
选项：`已走访␣`、全角的 `已走访` → 规范的 `已走访`。**不猜同义词**（`已访` 不会改成 `已走访`），猜错会让统计静默出错。

「汇总说明」加一节，写清自动规整了什么，并各举一个例子，让人一眼看出改得对不对：

```
自动规整（只改了汇总表，原文件没动）：
  走访日期  23 格  例：2026.10.5 → 2026-10-05；10月3日 → 2026-10-03
  户数       4 格  例：3户 → 3
  联系电话  11 格  例：138 **** 8000 → 138****8000（手机号的例子打码）
  没敢改的   2 格  东城 第 7 行「10.1」（分不清 10月1日 还是 10月10日），已标浅橙
```

例子出现在汇总表里没问题，汇总表本来就有全部内容；但**不进通报**（通报要发群）。手机号的例子照样打码，免得「汇总说明」被单独截图转发时带出号码。

`merge_step` 是内部技能分段续做用的入口，签名只**加一个可选参数** `rules=None`，不传的话行为不变。

**P2 延伸到普通汇总**：公开仓库的大多数人用的是不要名单、不要下发记录的普通汇总，那里没有规则可依。可以靠数据本身判断：一列里八成以上的非空格子已经是真日期，剩下认得出的文字日期就照上表规整。这是按**数据**推断，不是按**列名**猜，误伤面小得多。

## 7. 兼容性

| 场景 | 行为 |
|---|---|
| 不写括号 | 和 v2.10 逐字一致（回归用例守住） |

| `.xls` 输出 | 不存在（拆分产物都是 xlsx） |

## 11. 已定（作者 2026-10-11）

1. **文字日期算对**，汇总时统一改成真日期（§6.7）。数字形式的 `10.1` 有歧义，不改、标出来。
2. **「填写有误」单独作为一个状态**，不并进「有漏填」。
3. **超长选项不加下拉框**，只在查收时检查；不用命名区域（§5.1）。
