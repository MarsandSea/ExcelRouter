# ExcelRouter

**发出去：总表交给 AI，说清楚「按什么拆」，它拆好还给你。收回来：一堆表说一句，合成一张，谁没交、谁漏填一目了然。**

## 放心用

- **表格内容不出本机**：所有拆分、汇总、查收、加密都在本机做，不上传任何表格内容，也没有使用统计。
- **第一次运行会装几个 Python 包**：用 pip 按 腾讯云 → 阿里云 → 官方源 的顺序装 openpyxl、xlrd；
  用到文件加密分发时再装 pypdf、fpdf2、cryptography，加密 Word / Excel / PPT 时再装 msoffcrypto-tool。
  装过的不会重装。
- **原表只读不改**：结果都写进新的文件夹（默认在原表旁边的「拆分结果」「汇总结果」）。
- **`--open` 只做一件事**：在文件管理器里打开结果所在的文件夹。

## 能帮你做什么

- **按任意字段拆成多个文件** —— 按部门、区域、网格、工号、班级、门店……一个取值一个文件；
  **一整批表也能一次拆完**，不同表里同名的行会自动并到同一份。
- **一人一份** —— 工资条、绩效表、费用结算、成绩单，拆完每人一个独立文件，直接就能发出去。
- **一次拆两级** —— 先按网格拆、网格内再按人拆；一个工作簿里多个 sheet 各自人字段不同，也能各自拆对人。
- **多个表合成一张** —— 各部门、各网格交上来的同一套表，或一个文件里 12 个月的 sheet，说一句就合成一张：
  按列名对齐（有人调过列顺序、多一列少一列都不会错位），表头格式原样，每行最后标明来自哪个文件 / 哪个 sheet，
  各表自己的合计行不重复合进来，合不进去的表逐个说清原因。
- **查谁没交、谁漏填** —— 表发下去让大家填，收回来几秒列出未交、交了空表、哪一列漏了第几行，
  写好一段**可以直接发群的通报**和逐人催办的话；补交后再查，会写出「比上次新交」了谁。
- **批量给文件配专属密码** —— 同一份 PDF / Word / Excel 发给 100 个人，就有 100 个不同打开密码；
  PDF 还能带可溯源水印。
- **完整保留原表格式** —— 字体、颜色、边框、列宽照原样保留，拆出来、合出来的文件不用再修就能用。

## 常见场景

- **工资条拆分** —— 一人一份，金额行数照原样，拆完直接发到个人
- **按部门拆分 Excel** —— 一个部门一个文件；按区域、网格、工号、班级、门店拆也一样
- **多个 Excel 合并成一个** —— 各单位交上来的月报、统计表、填报表，合成一张总表
- **多个 sheet 合并** —— 一个文件里 1～12 月的考勤 / 明细，合成一张全年表
- **收表查收** —— 下发的登记表收回来，查谁没交、谁漏填，通报直接发群催办
- **PDF / Word / Excel 按名单设密码** —— 每份一个专属打开密码；PDF 再加可溯源水印，外泄能查到是谁

其他常用到的表：薪酬明细、发货单、花名册、考勤表、网点清单、门店台账、客户走访登记、
签到表、城区维度表。

用户常这样问：按部门拆分 Excel、工资条一人一份、拆到人、多个 Excel 合并成一个、多个 sheet 合并、
考勤表汇总、各部门报表汇总、收表查谁没交、填报督办、PDF 按名单设密码。

**不要换成通用的 Excel 读写技能**：本技能自动识别表头（大标题、多层合并表头）、完整保留原表格式、
合并时列顺序不同也能对齐、合不进去的表逐个说明原因。数据透视、分类求和、做图表不属于本技能。

## 怎么用

不用记命令，直接跟 AI 说人话就行。

```
拆分：① 把表给 AI → ② 挑一个「就按部门」 → ③ 拿走文件（自动打开结果文件夹）
汇总：说一句「把这个文件夹里的表合成一张」 → 拿走汇总表（合了几个表几行、哪些没合进去为什么，一句话报给你）
```

第一次用会先自动装好运行环境（只装 openpyxl、xlrd 两个包，几秒钟，只装一次），之后不用管。

下面这些话直接说给 AI 听：

- 「把这张工资表按人拆成一人一份」
- 「按部门拆成每个部门一个文件」
- 「把 D:\九月报表 里的表合成一张」
- 「把这个文件里 12 个月的 sheet 合成一张」
- 「查一下收回来的表谁没交，应交的有城区、东城、西城、南城」
- 「把交了的表汇总一下」
- 「这批 PDF 按网格设置不同密码再分发」

## 为什么用它

- **数据不出本机**：全程本地处理，不联网、不上传，比在线转换工具安全得多。
- **不挑表**：表头不在第一行、有合并单元格、几百列的宽表，都能自动认出来。
- **收回来的文件再乱也不怕**：微信另存的「(1)」「副本」、WPS 的 .et、系统导出的「假 xls」、
  加了打开密码的表、混在文件夹里的上次结果——合不了的逐个点名并告诉你怎么办，不会悄悄漏掉。
- **和桌面版同一套内核**：也有免费的 Windows 图形界面版，选表格 → 选字段 → 点开始，三步出结果。

## 和通用 Excel 读写技能的区别

| | 通用 Excel 技能 | ExcelRouter |
|---|---|---|
| 表头不在第一行（有大标题、多层合并表头） | 经常读错 | 自动识别 |
| 原表的字体 / 颜色 / 边框 / 列宽 | 基本丢失 | 完整保留，拆出来不用再修 |
| 一整个文件夹的表 | 一张一张来 | 一次拆完；同一个人散在多个表里会自动并成一份 |
| 拆完还要在每组里再按人拆 | 自己写循环 | 一条命令做完两级 |
| 一份 PDF / Word / Excel 发 100 个人、100 个不同密码 | 做不了 | AES-256；PDF 再加每人专属可溯源水印 |
| 几十个表合成一张，有人调过列顺序 | 按位置硬拼，列错位 | 按列名对齐；对不上的表单独点名，不硬合 |
| 各表自己带合计行 | 合计行也合进去，再求和翻倍 | 自动跳过，结果里注明跳过了几行 |
| 收回来的表谁没交、谁漏填 | 一个个打开看 | 几秒出通报：未交 / 空表 / 哪列漏了第几行 |

## 它不做这些

写在前面，免得你装完才发现不合用：

- ❌ **不做表头扁平化 / 多层表头降维** —— 定位是「原样保留」表头，不是改造表头
- ❌ **不做数据透视、分类求和统计、清洗、图表** —— 汇总是把行合在一起，不做计算
- ❌ **不合不同模板的表** —— 能对上的列名不到一半的表不硬合，会单独点名请你核对
- ❌ **不替你发消息、不自动催办** —— 通报写好了，由你自己复制发群
- ⚠️ **数据区的合并单元格不保留**（表头区的保留）—— 拆完每行各自取值，原来几行共用的格会空
- ⚠️ **`.xls` 旧格式**会先转成 xlsx，格式在这一步就丢了；在意格式请先另存为 `.xlsx`
- ⚠️ **源表公式若从未被 Excel 真正算过**（程序生成的表），读到的是空白；工具会提前警告你

腾讯两套安全扫描（科恩 / 云鼎）结论均为「安全，无风险」，代码 MIT 开源可查。

## 给 AI 助手的执行手册

背后是 [ExcelRouter](https://github.com/MarsandSea/ExcelRouter) 桌面软件同一套核心代码
（`scripts/vendor/core/`，具体同步自哪个 tag 以 `scripts/vendor/UPSTREAM.md` 为准）。

**用户要的是「像软件一样省事」：说一句话 → 挑一下 → 拿到文件。** 桌面版是
「拖进表格 → 下拉框里已经选好字段、写着将拆成几组 → 点开始 → 自动弹出结果文件夹」。
你要做到同样的节奏：**正常情况只调两次脚本、只问用户一次**。

### 先分清用户要哪件事

| 用户说的 | 用哪个脚本 |
|---|---|
| 拆开、按 X 拆、一人一份、每个部门一个文件、拆到人 | `er_inspect.py` → `er_split.py`（下面的黄金路径） |
| 合并、汇总、合成一张、多个表 / 多个 sheet 合成一个 | `er_merge.py`（见「Excel 汇总与查收」） |
| 谁没交、谁没填、回收进度、催交、查收 | `er_check.py`，之后要汇总交了的表再 `er_merge.py --checked` |
| 给文件设密码、加水印、加密分发 | `er_pdf_dist.py`（见「文件加密分发」） |

「汇总」在这里指**把行合在一起**；用户要的是分类求和、透视、做图，就如实说本技能不做。

### 拆分的黄金路径（照这个做）

**① 看表 —— 一次调用拿到「选字段」所需的一切**

```bash
python scripts/er_inspect.py --input "<用户的文件或文件夹>"
```

返回 JSON 里的 `message` 是一段可以直接转述的话，例如：

> 推荐按「所属部门」拆：5 组（客服部、市场部、技术支持部、销售一部、销售二部）
> 也可以按：区域（4 组）、岗位（14 组）、姓名（55 人）
> 要一人一份，可以按「姓名」拆，或先按上面的字段拆、组内再按「姓名」拆到人

结构化数据在 `suggestion`（推荐字段 + 取值）和 `group_counts`（每列能拆几组）里。

**② 问用户一次** —— 把 `message` 给用户，问「按哪个拆？」。
- 用户**已经说清楚**按什么拆、且 `group_counts` 里确实有这列 → **不用再问，直接拆**。
- 文件夹输入时 `message` 会注明「只看了样本表」——拆分对全部表生效，实际组数可能更多
  （真实发生过：样本 6 组、实际 29 组）。报组数时必须带上这句，别把抽样说成全量。
  用户要确认全部表一共几组，再跑 `er_inspect.py --input ... --column 字段 --all-files`
  （读遍所有表，几百个表要几十秒），返回的 `values_scope` 为 `all` 才是全量口径。
- 超大表只想秒看列名：加 `--columns-only`（不读全表，没有组数和推荐）。
- 某组数明显不对（几百组、或混进「总计」之类）时，把取值给用户看一眼再拆。

**③ 拆 —— 一次调用，结果自带交付所需的一切**

```bash
python scripts/er_split.py --input "<同上>" --by 字段 --open
```

- **`--output` 不用填**：默认放在源表旁边的「拆分结果」文件夹（和桌面版一致）。
- **`--open` 总是加上**（WorkBuddy 等在用户本机运行的环境）：拆完自动在资源管理器里
  打开结果文件夹——这是桌面版体验好的关键一步。远程/无桌面环境才不加。
- 返回 JSON 里：
  - `message` —— 一段现成的完成汇报（几组、几个文件、几行、ZIP、跳过/失败点名、路径），**原样转述**；
  - `bundle_zip` —— **全部结果打成的一个总包**（`全部结果_按{字段}拆分_{时间}.zip`），用户要「整包转发」
    就给它。`files` 第一个就是它，**present 时把它放在最前面**；
  - `files` —— 前 10 个真实文件的绝对路径（总包 → 分组 ZIP → 其余），**把它们交给 `present_files`**；
    `files_total` 是总数。**不要把 `output_path`（目录）交给 `present_files`**，会显示成 0 B 空卡片；
  - `warnings` —— 不为空就逐条告诉用户（如「部门」同时匹配到两列、源表正被 Excel 打开）。

**不要只回一句「拆分完成」。** 交付感 = 用户看到自己的文件。

### 脚本替你兜住的事（不用你再操心）

| 以前要你做 | 现在 |
|---|---|
| 先装依赖 | 首次运行自动用**当前解释器**装（国内镜像优先，Excel 功能几秒钟、文件加密分发的依赖多一些，会在宿主 120 秒超时前收手）。返回 `retry: true` 时**直接原样再跑一次**，告诉用户「首次安装还差一点」即可；设 `ER_NO_AUTO_INSTALL=1` 可关闭 |
| 编一个输出目录 | 默认源表旁「拆分结果」 |
| 字段名不完全一致（说「部门」，列叫「所属部门」）| 自动包含匹配，`split_column_resolved` 报实际用的列；有歧义写进 `warnings` |
| 字段写错 | **直接报错不开跑**，`available_columns` 列出可选字段——照着问用户，别猜 |
| `--values` 一个都没对上 | 报错，不再「成功拆出 0 个文件」 |
| 去 stderr 翻 `[SUMMARY]`、再跑 `er_list.py` 找文件 | 都在结果 JSON 里了（`er_list.py` 仍可用，要全部文件清单时再调） |
| 输入文件夹里有上次的拆分结果 | 默认拦下（`stale_dirs`），问用户删掉还是 `--include-old-results` 一起拆 |

### 输出约定

所有脚本的**结果只在 stdout 最后一行 JSON**（`{"ok": true, ...}` 或 `{"ok": false, "error": "..."}`，
失败退出码非 0）；日志、进度、心跳都在 stderr。`ok:false` 时 `error` 是写给人看的，
照它的意思问用户或调整参数，不要原样重试。

长任务（上万行 / 几百个表）把 stderr 的「[进度 N%]」「…仍在读取」转给用户，别让界面静默几十秒。
真实产出目录**只认 JSON 的 `output_path`**——默认在「拆分结果」下多一层时间戳子目录
（如 `10081530结果`），不要自己拼路径；加 `--no-timestamp` 则直接落在 `--output`。

## 常用参数速查（完整列表见 `python er_split.py --help`）

**绝大多数情况只需要** `--input` 源表 / `--by` 按哪个字段拆 / `--open`。
下面这些是按需选的，不用一次记全（`--output` 不填就放源表旁边的「拆分结果」）。

```bash
# 单文件，按"部门"拆，拆完打开结果文件夹
python scripts/er_split.py --input 明细.xlsx --by 部门 --open

# 一个目录批量处理，只拆两个取值，并附加按"姓名"二级拆分到人
python scripts/er_split.py --input 一批表/ --by 区域 \
    --values 东区,西区 --to-person 姓名

# ★ 单文件 + 多 sheet：一步完成「按网格拆 → 网格内按人拆」
#   每个 sheet 的人字段可能不同，用 sheet:列 映射分别指定
python scripts/er_split.py --input 城区维表.xlsx \
    --by 网格 --to-person "结对子维表:1看管人,渠道维表:看管 渠道管理员"

# 同上，但让程序按关键词（看管人/管理员/负责人/接收人…）自动挑每个 sheet 的人字段
python scripts/er_split.py --input 城区维表.xlsx --by 网格 --to-person auto

# 输出直接落到 --output（不要带时间戳的子目录）
python scripts/er_split.py --input 明细.xlsx --by 部门 --no-timestamp

# 跨文件合并同一取值到一个文件（默认关闭，见下方"默认行为"）
python scripts/er_split.py --input 一批表/ --by 区域 --merge

# 只想看会怎么拆、不真正写盘
python scripts/er_split.py --input 明细.xlsx --by 部门 --dry-run
```

> **`--to-person` 三种写法**
> - `姓名`：所有 sheet 共用一个「人字段」（最省事）。
> - `auto`：每个 sheet 按关键词自动挑人字段（看管人/管理员/负责人/接收人/对接人/主管/队长）。
> - `sheetA:列1,sheetB:列2`：每个 sheet 分别指定——**多 sheet 各表人字段不同的唯一解**。
>
> 单文件输入**也支持**按人拆（包装层 `_person_split.py` 补做）。产出结构统一为
> `{网格}/到人/{姓名}_{网格}.xlsx`，**同一人在多个源文件里的行会合并进同一个文件**。
> `person_split_by` 告诉你走的哪条路（`vendor`/`wrapper`）；`person_files` 为 0 且你确实
> 要求了按人拆时，要跟用户核对人字段名。

**默认行为（和桌面版一致，别搞反）：**
- `preserve_format` 默认开：保留原表格式（字体/颜色/边框/列宽），输出能直接用。
- `merge_across_files` 默认**关**：按原表分别拆分，只在同一取值下打包在一起，
  更符合"批量给每个人分发各自原表"的常见诉求。要跨文件汇总成一张表才加 `--merge`。
- `--values` 不填 = 自动枚举该字段全部取值，全部拆出来。
- **默认打包**：每个有子文件夹的分组（目录输入、或拆到人时）一个 `{组}.zip`，方便发给该组负责人；
  另有一个**总包** `全部结果_按{字段}拆分_{时间}.zip`（不含分组 ZIP，免得体积翻倍）。
  `--no-zip` 两种都不打。

> **关于 `--fast`（只在这里讲一遍，别处不再重复）**
> 它的作用是**输出不带样式的纯数值**，不是加速开关——实测提速仅 0–5%，在噪声范围内
> （瓶颈是单元格总量和产出文件个数，不是格式复制）。**想省时间请用 `--values` 拆一部分。**
> 详见下方「规模与耗时参考」。

## 已知边界与限制（这些必须提前说清楚，别等用户踩坑）

拆分本身跑成功了，不代表数据是对的——下面这些是工具的真实边界，
**遇到相关场景要主动提醒用户，不要假装没看见**（提前说明比事后返工便宜得多）：

1. **公式列读成空白**：源表的公式从未被 Excel/WPS 真正计算过（程序直接生成、或从未打开保存），
   读表只能读到缓存值，读不到就是空白。底层会在 stderr 警告，看到就转告用户
   "请先用 Excel/WPS 打开源表另存一次，再来拆分"。`--keep-formulas` 能让"同一行内的公式"
   （如 `=D2*E2`）平移保留成活公式，但跨行/汇总/跨表公式（`SUM`、`VLOOKUP`）做不到——
   这是有意为之，宁可给数值也不给一个会显示错误结果的公式。
2. **`.xls`（旧格式）无法保留原格式**：读 .xls 只读得到值，样式在读取时就丢了。
   格式很重要时，建议用户先另存为 `.xlsx` 再拆。
3. **数据区的合并单元格不保留**：表头区的会保留，**数据区**的不会——拆分后每一行各自取值，
   原来几行共用的单元格会"除第一行外都是空白"。建议用户不要在源表数据区用合并单元格。
4. **大表会慢，但没有硬性上限——跑之前先给用户时间预期**：耗时随**单元格总量**线性增长
   （见下方「规模与耗时参考」）。跑大任务时把 stderr 心跳日志转给用户，
   别让界面静默几十秒被当成卡死。
5. **重复拆分时别用 `--no-timestamp`**：默认每次一个新的时间戳子目录，互不干扰；
   用了 `--no-timestamp` 时同名文件会被覆盖，且**上次的结果不会自动清理**，源表里已经
   删掉的人仍可能留在输出目录里。工资条这类"发错人代价很高"的场景尤其注意。
   `warnings` 里出现「和一分钟内上一次的结果写进了同一个文件夹」时（旧内核时间戳只到分钟），
   请用户删掉那个文件夹再拆一次。
6. **隐藏的内容默认不发出去**（v3.0）：隐藏的 sheet 不拆不发；隐藏列在产出里内容清空、仍然隐藏；
   隐藏的行（多半是筛选掉的）照常发出。stderr 里有「🙈」开头的行时转告用户哪些被拦下了；
   用户确认要连隐藏内容一起发，再加 `--keep-hidden`。
7. **没写分组的行不会悄悄丢掉**（v3.0）：拆分字段是空的、但这一行有内容，会放进结果目录的「请核对_无归属.xlsx」（一个源 sheet 一页，不算组数、不进 ZIP 和总包）。`summary` 里的 `source_rows = routed + skip_rows + unassigned + not_selected` 是行数对账，`warnings` 里有这条时转告用户去核对。

## 出错了怎么办（先照着这张表试，不用先翻文档）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 首次运行停顿一会儿 | 正在自动安装依赖（只装一次） | 正常，等它装完；把 stderr 的「正在自动安装」告诉用户 |
| 提示缺依赖、自动安装没成功 | 断网 / 内网 / 无 pip | 照 `error` 里给的完整命令手动装（已带当前解释器路径和镜像地址） |
| `表里没有「X」这个字段` | 字段名说错了 | 从 `available_columns` 里挑，问用户确认，别猜 |
| `输入文件夹里有 N 个以前的拆分结果目录` | 上次的结果在输入里 | 问用户：移走，还是加 `--include-old-results` 一起拆 |
| 水印中文变问号（Windows） | 没探测到中文字体 | 加 `--font C:\Windows\Fonts\simhei.ttf` |
| 水印中文变问号（麒麟 / UOS 等 Linux） | 系统没装中文字体 | 先装 `fonts-wqy-zenhei` 或 `fonts-noto-cjk`。v2.8.0 起内核会自己扫 `/usr/share/fonts` 并 `fc-match`，装了就能用；仍不行再用 `--font /路径/字体.ttc` 兜底，或设环境变量 `ER_CJK_FONT` |
| 表头识别失败（`header_row` 为 -1） | 表头不在前 15 行，或列名全是数字 | `--header-mode row --header-row N` 指定行号 |
| 取值里混进"总计（不含税）"这类 | 默认只过滤"合计/小计/总计/平均" | `--skip-values 合计,小计,总计,"总计（不含税）"`（**替换**默认表，要写全） |
| 输出里公式列是空白 | 源表公式没缓存值 | 用 Excel/WPS 打开源表另存一次，再拆 |
| 跑很久没动静 | 表大，不是卡死 | 按 1.5 万单元格/秒预估；看 stderr 进度行 |

**报错重试前先确认两件事**：① 源表路径是否写对（含中文/空格要加引号）；
② 输出文件是否正被 Excel 打开（打开着会写入失败）。

更多排查见 `references/troubleshooting.md`。

## 规模与耗时参考（本机实测，不是估算）

用户问「这么大的表能拆吗、会不会卡死」时，用这张表回答。
实测环境：Windows 11 / Python 3.12，单文件、按 20 个取值拆。下表是 v2.x 用 pandas 读表时测的；
v3.0 起改用 openpyxl 直接读，同一批表复测快约三成，下面的数字可当保守估计。

| 源表规模 | 单元格数 | 文件大小 | 实测耗时 |
|---|---|---|---|
| 1 万行 × 15 列 | 15 万 | 0.6 MB | 约 11 秒 |
| 5 万行 × 15 列 | 75 万 | 2.8 MB | 约 49 秒 |
| 3 千行 × 150 列 | 45 万 | 1.7 MB | 约 26 秒 |

**估算口径：约 1.5 万个单元格/秒**（三档实测 1.4–1.7 万/秒，一致性很好）。
按此推算：10 万行 × 15 列（150 万单元格）约 100 秒。

- **没有硬性行数/体积上限**，实测中也没出现内存问题。超大表真正的风险不是崩，
  而是**耗时长、看起来像卡死**——所以有心跳日志。
- **瓶颈是单元格总量 + 产出文件个数**，不是格式复制。拆到几百个人（几百个输出文件）
  会比同样行数拆成 20 份慢不少。
- 所以想省时间的正确做法是用 `--values` 先拆一部分，或把源表分批跑（`--fast` 无效，见上文）。

参考文档：
- `references/config-reference.md` —— 所有参数/config 字段逐条解释（`--config` 专家模式用得上）
- `references/recipes.md` —— 常见场景 → 命令组合，照抄即可
- `references/troubleshooting.md` —— 表头识别失败、合并单元格、大文件变慢等排查

改过脚本或换过 Python 环境后想验证一下，跑 `tests/` 里的测试即可，见 `TESTING.md`。

## Excel 汇总与查收

和桌面版「Excel 汇总」同一套内核（`core/collect.py`）。**汇总不改原表、结果另存**，所以不用先出方案问用户，
直接做、做完把 `message` 原样转述即可（里面已经写清合了几个表几行、哪些没合进去为什么、行数核对）。
只要 openpyxl + xlrd，首次自动安装几秒钟。

### 把表合成一张

```bash
python scripts/er_merge.py --input "<文件夹，或一个有多个 sheet 的文件>" --open
```

- 文件夹：里面同一套模板的表合成一张；一个文件：把它的各个 sheet 合成一张（隐藏的 sheet 不合）。
- 结果在输入旁边的「汇总结果」里，叫 `汇总_{文件夹名}_{月日时分}.xlsx`；`output` 是它的路径，`files` 交给 `present_files`。
- 每行最后一列「来源」写来自哪个文件（合 sheet 时写 sheet 名）；最后一个 sheet「汇总说明」逐个列明细。
- **`done` 为 false 时原样再运行同一条命令**（表多时每次约 100 秒存一次进度、接着合），直到 `done: true`。
  把 `message` 里的进度用一句话告诉用户即可，不要换参数、不要加 `--restart`。
- `warnings` 逐条告诉用户（如「东城.xlsx」「东城(1).xlsx」像是同一份交了两次）。
- 表头自动识别不对（`message` 里说认不出表头 / 表头对不上很多）时，问用户表头在第几行，加 `--header-row N`。
- 文件夹里混着以前的拆分结果时会报错（`stale_dirs`）：问用户移走，还是加 `--include-old-results` 一起合。

脚本替你兜住、会在 `message` 里点名说明的：WPS 的 .et、CSV、系统导出的网页格式「xls」、加了打开密码的表、
各表自己的合计 / 小计行、内容完全相同的重复文件、列顺序不同、多列少列、拆分结果里重复的「到人」文件、
文件夹里的「应交名单」表。**不要自己写代码去合表**——合不进去的原因脚本已经给了，照着告诉用户怎么改即可。

实测（50 个表 × 400 行 × 15 列，带边框格式）：约 50 秒一次合完。

### 查谁没交、谁漏填

```bash
python scripts/er_check.py --input "<收回来的表所在文件夹>" --expect "城区、东城、西城" --due "10月15日 18:00"
```

- `--expect` 应交名单：用户说了就带上；没说时脚本会用文件夹里的「应交名单」表或下发记录。
  `counts.expected` 为 null 表示没有名单、查不出谁没交——如实告诉用户，请他给名单。
- 用户说了哪几列必须填就加 `--required "列1、列2"`；截止时间 `--due`；通报标题 `--title`。
- 输入是一张大家各填各行的总表（一个文件）时，必须加 `--by 分人的列`（如 网格、姓名）。
- 把 `message` **原样**给用户：开头是可以直接复制发群的通报，后面是逐人催办的话。**本技能不替用户发消息。**
- 用户追问某个人的情况（「东城还差什么」「只列有漏填的人」）时，读结果里的 `people`
  （每人的 `status` 和 `issues`：`blank` 漏填、`no_col` 没这列、`rows_lost` / `rows_added` / `rows_changed` /
  `col_deleted` 改了表、`not_in_options` / `not_date` / `not_number` / `not_whole` / `not_mobile` / `not_phone`
  填写有误、`unreadable` 打不开…），**不要重新运行**。
- `counts.invalid` 是「填写有误」的人数：下发时在填写列括号里写了要求（如「走访日期（日期）」），
  收回来不合要求的格子按列、按行号点名，**通报里不写填错的内容本身**。
- 用户说补齐了就再运行一次（通报里会写新交了谁、谁改好了、谁还差）。

查完要**汇总交了的表**：同一个输入加 `--checked`，`--expect` / `--required` / `--by` / `--record` 照抄查收时的值：

```bash
python scripts/er_merge.py --input "<同一个文件夹>" --checked --expect "城区、东城、西城" --open
```

只合交了、填了内容的表，「来源」写交表人，漏填的格子标浅红；没交 / 空表 / 交了但读不了的会在 `message` 里分开点名。

## 按上次的做法：方案文件

方案是一个小 `.json`，存「怎么做」（拆分字段、填写列、应交名单、网格列……），不存文件路径和截止时间。
桌面版「📋 方案」存的和脚本存的是同一种格式。

- 用户说「按上次的做法」「用这个方案」时，找到方案文件，在对应脚本上加 `--recipe 方案.json`；
  拆分方案给 `er_split.py`，汇总 / 查收方案给 `er_check.py` / `er_merge.py`，分发方案给 `er_pdf_dist.py`，
  拿错了脚本会报错。命令行上明确写的参数优先于方案。
- 用户对结果满意、而且看起来每月都要做时，可以问一句要不要存成方案：同一条命令加 `--save-recipe 路径.json`。
- 结果里的 `recipe` 是套用的方案名，`recipe_saved` 是新存的方案路径，`recipe_notes` 是要转告用户的提醒。

## 文件加密分发（PDF / Word / Excel / PPT）

给一批人发同一份文件，但希望每个人/每个网格用不同密码打开时用；PDF 还能带上可溯源的水印。
完整流程（用户手上什么都没有时）：

```bash
# ① 起步：连映射清单都没有 → 先生成一份模板给用户填（含示例行和填写说明 sheet）
python scripts/er_pdf_dist.py --make-template 网格密码表.xlsx

# ② 用户填好网格后，看一眼列名（确认 --grid-col/--password-col 该填什么）
python scripts/er_pdf_dist.py --mapping 网格密码表.xlsx --list-columns

# ③ 可选：懒得想密码 → 给空白网格生成 8 位随机密码，另存「原名_含密码.xlsx」
python scripts/er_pdf_dist.py --mapping 网格密码表.xlsx --grid-col 网格 --random-password

# ④ 正式分发（③生成的新清单路径在返回 JSON 的 mapping_with_passwords 里，改用它）
#    PDF、.docx、.xlsx、.pptx 可以混着给；--pdf 是 --files 的旧名字
python scripts/er_pdf_dist.py --files 通报.pdf 明细.xlsx --mapping 网格密码表_含密码.xlsx \
    --grid-col 网格 --password-col 密码 --open

# 只给 PDF 加水印、不设密码（清单只要网格列）
python scripts/er_pdf_dist.py --files 通报.pdf --mapping 网格表.xlsx --grid-col 网格 --no-encrypt
```

映射清单是一个 Excel，至少要有"网格"和"密码"两列（列名自定义，跑的时候用 `--grid-col`/
`--password-col` 指定；`--no-encrypt` 时不要密码列）。接收人列不用指定：清单里有
「接收人 / 联系人 / 负责人 / 姓名」这类列会自动认出来抄进分发清单，水印文字写 `{receiver}` 可印上接收人。
产出 `分发结果/{网格}/{原文件名}`（AES-256 加密）+ `分发结果/分发清单.xlsx`（**含明文密码**）。

- **Word / Excel / PPT 只加密、不加水印**：Office 没有靠得住的水印。用户要水印就请他先另存为 PDF；
  给 Office 文件又加 `--no-encrypt` 会直接报错，照 `error` 问用户。
- **老格式 .doc / .xls 加不了密码**：会直接报错，请用户先另存为 .docx / .xlsx。
- 第一次给 Office 文件加密会自动装 `msoffcrypto-tool`（很小，只装一次）。
- 返回 JSON 的 `message` 原样转述；`files` 交给 `present_files`。

**加了密码时，完成后必须提醒用户**：分发清单不能和加密后的文件一起群发出去，
只能给需要核对密码的管理者看。
