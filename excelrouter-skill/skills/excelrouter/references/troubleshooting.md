# 排查手册

## 表头识别失败（`er_inspect.py` 的 `header_row` 是 -1 或警告"没能识别出表头行"）

`auto` 模式是启发式的：扫描前 15 行，找"非空多、文字多、下一行像数据"的那一行。
遇到下面这些情况会失败或识别错：
- 表头前有超过 15 行的说明文字/空行——超出扫描范围，改用 `--header-mode row --header-row N` 直接指定。
- 表头本身几乎全是数字（比如列名就是年份"2024""2025"）——"看起来像文字"的判断会失真，同样建议手动指定行号。
- 多个 sheet 里格式不统一——`er_inspect.py` 只报告"首个可识别 sheet"的结果，如果目标数据在
  后面的 sheet，工具目前不支持按 sheet 名精确定位，需要先把目标 sheet 另存为单独文件。

如果表头位置在不同文件里不固定，但表头文字本身有固定的关键词组合，用关键词法兜底：
```bash
python scripts/er_split.py ... --header-mode keyword --grid-keys 网格 --id-keys 工号,姓名
```
表示"表头所在行必须同时包含'网格'和'工号'或'姓名'其中一个"。

## 拆分列的取值比预期多，混进了"合计"之类的汇总行

默认 `skip_values` 只过滤精确等于"合计/小计/总计/平均/空"的取值。如果汇总行写的是别的字样
（比如"总计（不含税）"），需要显式加进 `--skip-values`：
```bash
--skip-values 合计,小计,总计,平均,"总计（不含税）"
```
注意这会**替换**默认列表，不是追加，需要的项都要写全。

## 公式列在输出里是空白

工具读的是 Excel 文件里缓存的计算结果，不是重新计算。如果源文件是程序生成的、或者
公式从未被 Excel/WPS 真正打开计算过一次，就没有缓存值，读出来必然是空白——这不是 bug，
是 openpyxl 读取 xlsx 的机制限制。`er_split.py` 底层在处理时会检测这种情况并在
stderr 打印警告，看到就转告用户"请先用 Excel 或 WPS 打开源表，随便改一下再撤销、保存一次，
让公式产生缓存值，再重新拆分"。

## `.xls`（旧版 Excel 格式）拆完之后格式全丢了

工具用 xlrd 读 `.xls` 时只读得到值，样式信息在读取阶段就已经丢失，
`preserve_format`/`--fast` 在 `.xls` 源文件上没有区别。目前没有绕过办法，如果格式很重要，
建议用户先在 Excel/WPS 里把源文件另存为 `.xlsx` 再拆分。

## 数据区有合并单元格，拆分后错位或丢失

工具目前**不保留数据区的合并单元格**（表头区域的合并单元格没问题，会保留）。
如果数据行本身有合并单元格（比如"金额"列几行共用一个单元格），拆分后每一行会独立取值，
可能出现除第一行外都是空白的情况。这是已知限制，建议提醒用户源表尽量不要在数据区用合并单元格。

## 大文件/大批量跑得很慢，甚至看起来像卡住

- **先估时间，别急着判断"卡死"**：耗时基本随单元格总量线性增长，约 **1.5 万个单元格/秒**
  （实测：1 万行×15 列约 11 秒，5 万行×15 列约 49 秒，3 千行×150 列约 26 秒）。
  完整表格见 SKILL.md 的「规模与耗时参考」。
- 真要省时间：用 `--values` 只拆一部分，或把源表分批处理。
  （注：`--fast` 不是加速开关，实测提速 0–5%，详见 SKILL.md。）
- 进度通过 stderr 的 `[进度 N%]` 行汇报；如果长时间停在同一个百分比，看有没有报警告/错误。
- `--merge` 会把所有输出工作簿整批留在内存到最后统一保存，宽表+大批量文件时内存压力更大，
  非必要不加这个选项。

## 提示缺依赖、自动安装没成功，或者提示缺 pypdf/fpdf2/cryptography

脚本首次运行会用**当前解释器**（`sys.executable -m pip`）自动安装依赖：依次试腾讯云、阿里云镜像和官方源（用户自己配过 pip 源则只用他的），总时长控制在 95 秒内——WorkBuddy 会强制结束超过 120 秒的命令。没装完会返回 `retry: true`，再跑一次即可接着装。
仍失败（断网、内网、没有 pip）时，`error` 里会给出一条带解释器绝对路径的完整命令，照着手动跑即可——
**别用裸 `pip`**，多个 Python 并存时它常装到别的环境里，装完照样报缺。
受管环境不希望脚本自动装包，设环境变量 `ER_NO_AUTO_INSTALL=1`。

Excel 拆分、汇总、查收只需要 `openpyxl`/`xlrd` 这两个，文件加密分发才需要 `pypdf`/`fpdf2`；
给 Word / Excel / PPT 加密还要 `msoffcrypto-tool`（只在传了这类文件时才检查和安装）。
如果只做 Excel 拆分，分发相关依赖装不上可以先忽略。`cryptography` 缺失不会导致 PDF 分发
报错，只是加密强度从 AES-256 降级为 RC4-128（stderr 会警告，功能仍然可用）。

## 给 Excel / Word 加密时报「老格式，加不了密码」或「只能加密、不能加水印」

- `.doc` / `.xls` / `.ppt` 是老格式，请用户用 Word / Excel / WPS 另存为 `.docx` / `.xlsx` / `.pptx`。
- Word / Excel / PPT 不加水印。用户要水印就请他先另存为 PDF；只要密码就去掉 `--no-encrypt`。
- 文件本身已经设了打开密码的会被跳过（stderr 点名），请用户先去掉密码另存。

## PDF 水印里的中文变成了问号

水印生成用的字体是自动探测 Windows 系统字体目录（`simhei.ttf` 等）；非 Windows 环境、
或者 Windows 上确实没装中文字体时探测不到，会在 stderr 警告并继续（水印仍会加，只是
中文字符显示不出来）。这时用 `--font 字体文件.ttf` 指定一个含中文字形的 TTF 字体路径
（`.ttf`/`.otf`/`.ttc` 都可以；fpdf2 2.8 起支持字体合集）。
