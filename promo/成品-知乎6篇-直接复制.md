# 第 1 篇 · 问题：excel 怎么按部门拆分成多个文件发给各负责人？

**也适用于**：如何把一个 excel 表按某列拆成多个工作簿 / excel 批量拆分并分别发送

## 【正文】

```
先说结论：不用 VBA，不用写宏，也不用一个个复制另存。

这个问题下面很多答案在教 VBA，能用，但对大多数人有个门槛——你得敢在 Excel 里开宏、会改代码里的字段名。这件事其实有三种做法，按成本从低到高排：

【方案一：Power Query，零代码】
数据 → 获取和转换 → 按部门筛选后导出。
优点：Excel 自带，不用装东西。
缺点：部门多了要重复 N 遍；最致命的是它会把原表格式洗掉——合并表头、条件格式、列宽全丢。如果拆完是要发给部门负责人看的，基本得重新排版一遍。

【方案二：VBA 宏】
搜「Excel 按列拆分 VBA」能出来一堆。
优点：免费、可定制。
缺点：宏安全性要手动开；代码里的字段名是写死的，换张表就得改；大表容易卡；还有个实际问题——带宏的文件发给同事，不少公司邮箱直接拦截。

【方案三：专门的拆分工具】
这类工具解决的就是「保留格式」这件事：拆出来的每个文件，表头、颜色、合并单元格、列宽跟原表一模一样，不用二次排版。
还有个 VBA 不擅长的场景：整个文件夹十几张表，同一部门的先合并再拆。手工做是灾难。
最拉开差距的是二级拆分——先按部门拆，再在每个部门里按人拆成一人一份（发工资条就是这么用）。我见过的 VBA 方案基本只做一层，要加第二层等于重写逻辑；而支持二级的工具是一次跑完，汇总和每人一份两套结果同时出来。
更细的控制：可以只对文件名含特定关键字的表拆到人（比如只拆「工资」表，其他表照常按部门拆），一批表里混两种规则也能一次搞定。

我自己在用的是一个开源小工具（ExcelRouter，GitHub 上搜得到，MIT 协议免费），Windows 上跑，不联网——这点对处理工资、客户资料这类数据挺重要，文件不上传。整个文件夹丢进去，选个字段，出来就是分好的文件和打包好的 zip。

顺带说个可能有用的：它有两条入口，看你和谁配合。
· 给同事用的是 Windows 桌面版：不用装、不用看命令行，打开就是「选表 → 选字段 → 开始」三步。
· 给已经在用 AI 工具的人（Claude Code、WorkBuddy 这类）有配套的 Skill 包：装好后说人话就行——「把 examples 里这几个月的表按区域拆开，再拆到每个人」，AI 自己去调内核跑完，软件都不用打开，命令行也不用敲。
这两层共用同一套核心代码，所以同事用界面拆、我用 AI 拆，出来的结果行为完全一致，不会出现「你拆的和他拆的格式不一样」这种扯皮。
当然，如果你不用 AI 工具，上面这段直接跳过就行——桌面版本身就是完整功能，不依赖任何 AI 服务。

怎么选，看你的具体情况：
· 一次性、格式无所谓 → Power Query 够了
· 长期每周做、格式要保留、数据敏感 → 老老实实用专门工具
· 已经在用 AI 编程助手 → 装它的 Skill，连软件都不用开
· 想练手、喜欢折腾 → VBA，顺便还能学到东西

最后提醒一句：不管用哪种方案，拆之前先备份原表，先拿小样本跑一遍。批量操作一旦覆盖错了，找回来的成本远高于省下来的那几分钟。
```

# 第 2 篇 · 问题：excel 工资条怎么一人一份发？

**也适用于**：工资表怎么拆成每个人独立文件 / 怎么让员工只看到自己的工资条

## 【正文】

```
先说结论：这件事的核心不是「怎么拆」，是「怎么保证谁也看不到别人的」。

见过太多做法是整张表发群里让大家自己找，或者在群里单独发某人的截图——前者不合规，后者累死还容易发错。

正经做法就三种，按成本从低到高排：

【一、邮件合并（Outlook / Word）】
Office 自带，零成本，一次能发几百人。
缺点：格式基本没有——多层表头、颜色、合并单元格全丢，只能塞进几个纯文本字段；也做不了附件。
适合：只有「姓名 + 几个数字」这种简单通知。

【二、写脚本逐个生成】
用 Python 读总表，按姓名分组，每组另存成一个文件。要自动发的话再挂上邮件库逐封发。
优点：格式可控、逻辑透明，想怎么改怎么改。
缺点：需要编程能力；工资列一变动就得改代码；公司邮箱对批量外发往往有限制甚至拦截。
这条路对偶尔用一次的人不划算，对每月都做、又有编程基础的人是最灵活的。

【三、本地批量拆分工具】
关键点：必须在本机跑。工资数据过一遍公网服务，性质就变了。
一张表进去，N 个 xlsx 出来，一人一份，原格式保留。想按部门打包，就一次打成 zip 直接群发。
还能做二级：先按部门拆开，部门内再按人拆到每个人——一次运行同时出「部门汇总」和「每人一份」两套结果。

这类事我现在用一个本地小工具做（ExcelRouter，开源 MIT）。它就是为这个场景做的：选一张表，指定「姓名」列，出来就是每人一个文件，表头格式保留。不联网，断网也能用——这点对工资这种数据很重要。

怎么选：
· 字段少、格式无所谓 → 邮件合并够了
· 每月都要做、格式有要求 → 用本机工具
· 还要按部门再汇总一层 → 选支持二级拆分的
· 已经在用 AI 助手 → 它还有配套的 Skill，说句话让 AI 拆，和桌面版共用同一套内核

最后还是提醒一句：不管用哪种，拆之前先备份原表，先拿两三行的小样本跑一遍。工资这种数据，错一次的成本远高于准备花的时间。
```

# 第 3 篇 · 问题：让 AI 处理公司表格，数据会不会传到网上？

**也适用于**：用 AI 处理公司文件安全吗 / AI 会不会泄露我的数据 / 不敢把工作文件给 AI

## 【正文】

```
这个担心是对的。大部分人被这个问题卡住，是因为把两件完全不同的事混成了一件。拆开看就清楚了。

【一、「让 AI 想办法」和「让程序去跑」是两回事】
前者：你把数据贴给它，数据确实过网了——所以这一步只给脱敏的假数据，让它写方法、写脚本。
后者：脚本在你本机跑，读本地文件、写本地目录，全程不联网，断网也能跑。
一句话原则：敏感的事让 AI 想办法，别让 AI 碰真数据。

【二、怎么判断一个工具到底联不联网】
· 断网测一次：关掉 WiFi 再跑，能跑基本就是纯本地
· 看隐私政策里有没有「上传」「云端处理」这类字样
· 开系统流量监控，看它运行的时候有没有对外请求
这三条比任何宣传都可靠。

【三、公司环境的现实约束】
很多单位有明文规定，禁止把工作数据传到外部服务。本地工具不存在这个问题，报备也简单。
所以真正的问题不是「AI 行不行」，是「数据在哪跑」。

我现在处理工资、客户资料，都按这个原则来：让 AI 帮我想方法，但真数据只在本机跑，不上传。
这也是我当初选工具时唯一的硬标准——功能差一点没关系，数据不出本机这条不能让。
```

# 第 4 篇 · 问题：AI 写的代码能直接用吗？有哪些坑？

**也适用于**：AI 写的代码可靠吗 / AI 编程有哪些坑 / 用 Cursor、Copilot 写代码要注意什么

> 说明：**这篇不提产品**，纯干货，专门用来攒专业度。

## 【正文】

```
AI 写代码，现在真的快。但快不等于能用——我最近刚被自己坑了一把。

有个同步文件的小脚本，跑了一年都好好的。某天我把工作目录挪了个位置，再跑，报错：「真源目录不存在」。
查了半天，第一行写着：

SRC = r"D:\某个具体路径\..."

写死的绝对路径。目录一挪，它就找不到家了。

这个写法在 AI 生成的代码里特别常见，因为它不知道你以后会把东西搬到哪。下面这四条，都是我自己踩出来的。

【一、路径写死】
改法就一行：用当前文件的位置去推。
原则：脚本要跟着文件夹走，不能跟着某台电脑走。
顺带一个 Windows 的坑：路径里有反斜杠，字符串前面记得加 r，或者干脆统一用 pathlib。

【二、删文件的操作没有预览】
AI 很爱写整套删除、重建目录的操作。
我的规矩：凡是删除或覆盖的操作，先 dry-run 把要动的路径打印一遍给我看，确认了再真跑。
真实经历：差点把一个目录整个重建掉。

【三、异常被吞掉】
空 except 是最恶心的写法。
静默失败比崩溃可怕得多——崩溃你知道出事了，静默你还以为它成功了。
至少要把异常打出来或者记日志，让它炸给你看。

【四、没有边界检查就循环】
大文件一次性读进内存、几万行逐行写。
表现是：小样本一切正常，真实数据一跑就卡死。
检查点：有没有分块读？有没有开只读模式？内存峰值估算过吗？

用 AI 写代码，我现在固定三条规矩：
1. 路径一律相对推导，不许写死
2. 凡是删文件、覆盖目录，先打印一遍给我看
3. 报错不许吞，静默失败最可怕

AI 负责写得快，review 的责任还在人身上。尤其是会删文件、会改线上配置的那部分代码，一定自己一行一行看完。
```

**评论区（可选）**：
> 补一句：这四条里，路径和删文件最容易出事，建议优先检查这两块。

# 第 5 篇 · 问题：不用 VBA，怎么批量拆分 Excel 并保留原格式？

**也适用于**：excel 拆分怎么保留原格式 / excel 按列拆分有没有不改格式的方法

## 【正文】

```
大部分拆 Excel 的方案都死在同一个地方：拆是拆开了，格式全没了。

多层表头被压成一行、合并单元格散了、条件格式和列宽全丢——结果每个文件还得重新排一遍版。部门少还能忍，十几个分组的时候，比重做还慢。

【为什么格式会丢】
Power Query 和 pandas 走的是「读数据」路线，压根不处理格式；VBA 复制粘贴能保一部分，但合并单元格、条件格式经常掉。
根因在于：格式信息存在 xlsx 文件内部（样式表、合并区域、列宽定义），它不是单元格值的一部分。只搬值，格式自然全丢。

【三种方案的保留能力】
· Power Query：多层表头丢、合并单元格丢、条件格式丢、列宽丢
· VBA：多层表头部分保留、合并单元格部分保留、条件格式丢、列宽部分保留
· 专门工具：四项全部保留

【批量场景下还会多两个坑】
一是整个文件夹几十张表，同名数据是自动合并还是各自为政；
二是拆完还要打包分发，能不能自动打成 zip。

所以如果你拆完是要发给别人看的，选方案之前先确认它的格式保留能力，别等拆完才发现要重排一遍。

【顺带一提】
我后来用的是专门做这件事的工具，保留格式是它的核心能力，不是附带功能——多层表头、合并单元格、列宽颜色都能原样带过去。另外它是本地跑的，这点对我处理工作数据很重要。二级拆分也支持：先按部门拆、再按人拆，一次出两套结果。

【怎么选】
· 单行普通表、格式无所谓 → Power Query 够了
· 格式无所谓但要自动化 → 写脚本
· 有多层表头或合并单元格 → 别在 VBA 上耗时间，直接找保留格式的方案

选方案前先看你自己的表头结构，这一步比选工具更重要。
```

# 第 6 篇 · 问题：有什么办法能把 AI 接进日常办公流程？

**也适用于**：怎么让 AI 帮我做实际工作 / AI 除了聊天还能干什么 / AI Agent、Skill 怎么用

> 这篇是**独家篇**，整篇就讲 Skill，可以放开说。**结尾那句「不用 AI 也行」必须有。**

## 【正文】

```
大部分人用 AI 停在两个阶段：问问题、写文案。这两个都只在「生成」这一步打转——AI 拿不到你的文件，也执行不了任何操作。

真正让它干活，是第三步：给它工具。

我自己的做法，是把一件重复的工作做成一个「技能」，AI 需要的时候自己加载、自己调用。举个具体的例子。

【一、一次操作长什么样】
我说：「把这个文件夹里几个月的明细，按区域拆开，每个区域里再按姓名拆到每个人。」
AI 接着：识别需求 → 加载对应技能 → 执行 → 把结果汇报给我。
全程我没写代码、没打开 Excel。结果文件夹里是各区域的汇总表，每个区域下面还有一个「到人」文件夹，一人一份。

【二、它和「让 AI 写完代码再粘过去跑」的区别】
前者：AI 自己知道什么时候该用、参数怎么填；
后者：每次都要你重新把上下文描述一遍。
打个比方：前者相当于装了个 App，后者是每次现场抄一段代码。

【三、这种方式的边界】——说实话反而更可信
适合：明确的、重复的、做法固定的动作。
不适合：一次性的、需要大量判断的事。
前提：动作本身是确定性的，有清楚的输入和输出。

【四、我为什么还保留了桌面界面】
同一套内核，两套入口。我用 AI，同事用图形界面，**出来的结果完全一致**。
这点很重要——不然会出现「你拆的和他拆的不一样」这种扯皮，那就没法协作了。

【五、这个技能本身】
它是开源的，GitHub 上搜 ExcelRouter 就能找到（MIT 协议），桌面版和 AI 技能版共用同一套内核。
当然，不用 AI 工具也有完整的桌面版，用不用 AI 不影响功能——这一点要说清楚，免得有人以为必须先会用 AI。

【判断标准】
AI 不是用来聊天的，是用来接活的。
一件事如果你每周都要做、而且做法固定，那它就该被做成工具。
```
