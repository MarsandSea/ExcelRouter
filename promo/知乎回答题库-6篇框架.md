## 发布方式：回答别人的问题（主）· 自己发文章（辅）· 自问自答（备用）

| 方式 | 流量来源 | 建议 | 用在哪 |
|---|---|---|---|
| **回答已有问题** | 问题自带的关注量 + 搜索 | ⭐ **主力，6 篇里 5 篇走这条** | 有现成问题可答的 |
| **自己发文章** | 推荐 + 搜索收录，量小 | 🟡 **辅**，主要作用是被百度/AI 抓取（GEO） | 没有合适问题、内容又成体系时 |
| **自问自答** | 全靠自己带，问题没关注就没人看 | 🔴 **别当主力** | 只在领域内确实搜不到问题时用 |
| 想法 | 几乎没有 | ❌ 别做 | — |

**为什么主战场是"回答"**：知乎的钱在**问题存量**上。一个关注 >500 的问题自带流量池，
你答完就挂在那儿吃 1-2 年；自己新开的问题关注为 0，等于要从零养起来，新号没这个能力。

**自己发文章什么时候值得做**：
- GEO 目标（让豆包/百度搜得到）本来就需要**更多被收录的公开页面**，知乎文章是合法来源之一；
- 文章能自己起标题、写成完整教程（如「Excel 批量拆分 5 种方案对比」），比回答更适合当**长文资产**；
- 但别指望它自带流量——它的价值是**被搜到、被 AI 抓**。

**自问自答怎么用（备用）**：
第 6 篇（把 AI 接进日常办公流程）很可能搜不到合适的问题——那就自己提一个问题再自答，
或者直接发文章。判断标准：搜目标词，**如果没有「关注 >100 且回答 <20」的现成问题**，才自己开。

**节奏（避免被判营销号）**：
- 一周 1-2 篇，别一天连着发
- 先答 3 篇纯干货（第 4 篇那种不提产品的），再开始提产品
- 主页简介写一句产品名，但别放外链（知乎简介放外链有时会被清）

## 第 2 篇 · 工资条怎么做成一人一份？

**问法**
- excel 工资条怎么一人一份发
- 工资表怎么拆成每个人的独立文件
- 怎么让员工只看到自己的工资条

**开头段（直接复制）**

```
这件事的核心不是"怎么拆"，是"怎么保证谁也看不到别人的"。

见过太多做法是：整张表发群里让大家自己找，
或者在群里@某个人单独发截图——前者违规，后者累死还容易发错。

正经做法就三种，按成本从低到高排：
```

**主体框架**

1. **邮件合并（Outlook / Word）**
   - 优点：Office 自带，零成本，一次能发几百人
   - 缺点：**格式基本没有**——多层表头、颜色、合并单元格全丢，
     只能塞进几个纯文本字段；附件也做不了
   - 适合：只有「姓名 + 几个数字」这种简单通知的场景

2. **写脚本逐个生成 + 自动发邮件**
   - Python + smtplib，每个人一个附件
   - 优点：格式可控
   - 缺点：需要编程能力，工资列一变动就得改代码；
     公司邮箱对批量外发往往有限制甚至拦截

3. **本地批量拆分工具**
   - 关键点：**必须在本机跑**。工资数据过一遍公网服务，性质就变了
   - 一张表进去，N 个 xlsx 出来，一人一份，原格式保留
   - 还能做二级：先按部门拆，部门内再按人——一次的到两套结果

**产品露出（放在方案 3 之后）**

```
这类事我现在是用一个本地小工具做（ExcelRouter，开源 MIT），
它就是为了解决这个场景：选一张表，指定「姓名」列，
出来就是每人一个文件，原格式保留。
不联网，断网也能用——这点对工资这种数据很重要。
```

**怎么选**

```
· 字段少、格式无所谓 → 邮件合并够了
· 每月都要做、格式有要求 → 用本机工具
· 还要按部门再汇总一层 → 选支持二级拆分的
```

**收尾提醒**

```
最后提醒：不管用哪种，拆之前先备份原表，
并且先拿两三行的小样本跑一遍。
工资这种数据，错一次的成本远高于准备花的时间。
```

## 第 3 篇 · 让 AI 处理公司表格，数据会不会传到网上？

**问法**
- 用 AI 处理公司文件安全吗
- AI 会不会泄露我的数据
- 不敢把工作文件给 AI 怎么办

**开头段（直接复制）**

```
这个担心是对的，而且大部分人被这个问题卡住，
是因为把两件完全不同的事混在一起了。

拆开看就清楚了：
```

**主体框架**

1. **「让 AI 想办法」和「让程序去跑」是两回事**
   - 前者：数据确实过网 → 所以只给**脱敏的假数据**
   - 后者：程序在你本机跑，读本地文件、写本地目录，**全程不联网**
   - 一句话原则：**敏感的事让 AI 想办法，别让 AI 碰真数据**

2. **怎么判断一个工具到底联不联网**
   - 断网测一次：拔网线/关 WiFi 再跑，能跑就是纯本地
   - 看它的隐私政策有没有「上传」「云端处理」字样
   - 开流量监控看有没有异常请求
   - （这一条是干货，很多人不会）

3. **公司环境的现实约束**
   - 很多单位有规定禁止往外部服务传工作数据
   - 本地工具不存在这个问题，报备也简单

**产品露出（这里要克制，1 句）**

```
我现在做这件事用的工具是本地跑的（数据不出本机的那种），
这也是当初选它而不是在线服务的唯一原因。
```

**收尾提醒**

```
不要因为"听说很方便"就把工资表、客户名单丢进在线对话里。
那玩意一旦传上去，就收不回来了。
```

## 第 4 篇 · AI 写的代码能直接用吗？

**问法**
- AI 写的代码可靠吗
- AI 编程有哪些坑
- 用 Cursor/Copilot 写代码要注意什么

**开头段（直接复制）**

```
AI 写代码，现在真的快。
但快不等于能用——我最近刚被自己坑了一把。

有个同步文件的小脚本，跑了一年好好的。
某天我把工作目录挪了个位置，再跑：
「真源目录不存在」。

查了半天，第一行写着：
SRC = "D:\\某个具体路径\\..."

写死的绝对路径。目录一挪，它就找不到家了。
```

**主体框架（每条都是你可写的真素材）**

1. **路径写死** —— 上面那个例子
   - 改法：`Path(__file__).parent / "子目录"`
   - 原则：**脚本要跟着文件夹走，不能跟着某台电脑走**

2. **删文件的操作没有预览**
   - AI 很爱写 `shutil.rmtree`、`os.remove`
   - 我的规矩：凡是删东西，先 dry-run 打印一遍给我看
   - 真实经历：差点把目录整个重建掉

3. **异常被吞掉**
   - `except: pass` 是最恶心的写法
   - 静默失败比崩溃可怕得多——崩溃你知道，静默你以为它成功了

4. **没有边界检查就循环**
   - 大文件一次性读进内存、几万行逐行写
   - 表现：小样本正常，真实数据就卡死

**产品露出（可选，这篇其实可以完全不提产品）**

```
这几条都是我自己在项目里踩出来的，
不是从哪篇教程看来的。
```

> 这篇**可以不提产品**。纯技术输出对建立专业度最有效，
> 攒够了信任，后面提什么都有人信。

**收尾提醒**

```
AI 负责写得快，review 的责任还在人身上。
尤其是会删文件、会改线上配置的那部分代码，
一定要自己一行一行看完。
```

## 第 5 篇 · 不用 VBA，怎么批量拆分 Excel 并保留原格式？

**问法**
- excel 拆分怎么保留原格式
- 不用 VBA 怎么拆分 excel
- excel 按列拆分有没有不改格式的方法

**开头段（直接复制）**

```
大部分拆 Excel 的方案都死在同一个地方：
拆是拆开了，格式全没了。

多层表头被压成一行、合并单元格散了、
条件格式和列宽全丢——结果每个文件还得重新排一遍版。
部门少的时候忍忍就过去了，
十几个分组的时候，比重做还慢。
```

**主体框架**

1. **为什么格式会丢**
   - Power Query / pandas：走的是「读数据」路线，压根不处理格式
   - VBA 复制粘贴：能保一部分，但合并单元格和条件格式经常掉
   - 根因：**格式信息藏在 openpyxl/xlsx 内部，不是单元格值的一部分**

2. **三种方案的保留能力对比**（做成表格）
   | 方案 | 多层表头 | 合并单元格 | 条件格式 | 列宽 |
   |---|---|---|---|---|
   | Power Query | ❌ | ❌ | ❌ | ❌ |
   | VBA | ⚠️ | ⚠️ | ❌ | ⚠️ |
   | 专门工具 | ✅ | ✅ | ✅ | ✅ |

3. **批量场景下还会多两个坑**
   - 一整个文件夹几十张表，同名数据是自动合并还是各自为政
   - 拆完还要打包分发，能不能自动打 zip

**产品露出**

```
所以我后来用的是专门做这件事的工具（保留格式是它的核心能力，
不是附带功能）。另外它是本地跑的，这点对我处理工作数据很重要。
```

**收尾提醒**

```
选方案前先看你的表头是什么结构。
如果是单行的普通表，Power Query 够了；
一旦有多层表头或合并单元格，别浪费时间在 VBA 上——
直接找保留格式的方案。
```

## 第 6 篇 · 有什么办法能把 AI 接进日常办公流程？（独家篇）

**问法**
- 怎么让 AI 帮我做实际工作
- AI 除了聊天还能干什么
- 有没有能把 AI 用在办公上的方法
- AI Agent / Skill 怎么用

> ⚠️ 这是你最独家的一篇——别人只能讲概念，
> 你真的做了个能被 AI 调用的东西。**重点投入。**

**开头段（直接复制）**

```
大部分人用 AI 停留在两个阶段：问问题、写文案。
这两个都只在"生成"这一步打转，AI 拿不到你的文件，
也执行不了任何操作。

真正让它干活，是第三步：给它工具。

我自己的做法是把一件重复的工作做成一个"技能"，
AI 需要的时候自己加载、自己调用。
举个具体的例子。
```

**主体框架**

1. **具体到一次操作长什么样**
   - 我说："把这个文件夹里几个月的明细，按区域拆开，再拆到每个人"
   - AI：识别需求 → 加载对应技能 → 执行 → 汇报结果
   - 全程我没写代码、没开 Excel
   - **配图**：对话截图 + 结果文件夹截图

2. **它和「写完代码粘贴过去」的区别**（这是关键认知）
   - 前者：AI 自己知道什么时候该用、参数怎么填
   - 后者：每次都要你重新把上下文描述一遍
   - 类比：前者是装了个 App，后者是每次现场抄一段代码跑

3. **这种方式的边界**（诚实说，反而更可信）
   - 适合：明确重复的动作
   - 不适合：一次性的、需要大量判断的事
   - 前提：动作本身是确定性的，有输入输出规范

4. **我为什么还保留了桌面界面**
   - 同一套内核两套入口
   - 我用 AI，同事用界面，**结果完全一致**
   - 这点很重要：不然会出现"你拆的和他拆的不一样"

**产品露出（这篇可以放开说，因为整篇就是讲它）**

```
这个技能是开源的（GitHub 上搜 ExcelRouter），
桌面版和 AI 技能版共用同一套内核，
所以两边拆出来的东西不会有差别。

当然，不用 AI 工具也有完整的桌面版，
用不用 AI 不影响功能。
```

> ⚠️ 结尾这句必须有——避免非技术读者以为必须会用 AI。

**收尾**

```
AI 不是用来聊天的，是用来接活的。
判断标准很简单：
如果一件事你每周都要做，而且做法固定，
那它就该被做成工具。
```

**CSDN 标题的三个特点**（照着改就行）：
- 带具体技术词（Python / 邮件合并 / 封装）——SEO 靠这些词
- 带方案感（对比 / 三条路 / 附修复）——开发者爱点
- 不用问号——CSDN 是"找答案"，不是"看讨论"

## CSDN 版的三处调整

1. **加代码块**。哪怕只有几行，CSDN 读者默认要有代码。
   篇 4 直接贴 `Path(__file__).parent` 那段前后对比，篇 5 贴个最小示例。
2. **去掉口语词**。"我最近刚被自己坑了一把" → "最近遇到一个典型问题"。
   知乎的口语化在 CSDN 会显得不专业。
3. **加「总结」段**。CSDN 读者习惯看到结论清单，文末补 3-5 条要点。
